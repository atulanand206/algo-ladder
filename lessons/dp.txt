### memo
--idea
Memoization means "write the answer down the first time you work it out, and look it up every time after". A plain recursive function often asks the same question many times. Computing the stairs-climbing count for 30 steps by plain recursion re-solves the same small questions millions of times. Keep a notebook (an array or a map) keyed by the question, and the repeats cost almost nothing.
It works because the answer to a question depends only on the question itself, not on how you reached it. So the first answer is the answer forever. This is the top-down form of dynamic programming (DP, solving a big problem from remembered answers to smaller ones). The bottom-up form fills the notebook in a planned order instead of on demand.
--build
1. Write the plain recursion first. State what the function means in one sentence. Here `f(n)` is the number of ordered ways to climb exactly `n` stairs when each move is one of the sizes in `steps`.
2. Transition: `f(n) = sum of f(n - s)` over every step size `s` with `s <= n`.
3. Base case: `f(0) = 1`, because there is exactly one way to be done: make no more moves.
4. Add the notebook `memo`, sized `n + 1`, filled with a marker meaning "not computed" (here `-1`). At the top of `f`, if `memo[n]` is not the marker, return it. Before returning a new answer, store it in `memo[n]`.
5. Order to fill: you do not choose one. The recursion computes the smaller states on demand, each one once.
6. Read the answer: it is the return value of `f(n)`, the original question.
--think
- Signal: the recursion calls itself with arguments from a small set, and different branches reach the same arguments. Draw the call tree on a small input. If a node appears twice, memoize.
- Choose the state as the smallest set of numbers that fully describes the remaining problem. Everything else (the history of choices) must not matter. If it matters, put it in the state or this is not a DP.
- Top-down versus bottom-up: top-down is easier to write and only visits states that are reachable. Bottom-up avoids recursion depth limits and is easier to shrink in memory. Start top-down, then convert if depth is an issue (depth about 10 thousand in Python, a few thousand to a hundred thousand in Java or C++ depending on stack size).
- A map keyed by a tuple replaces the array when the state is sparse or has large values.
- Pitfalls: using `0` as the "not computed" marker when `0` is a valid answer; memoizing a function that also depends on a global that changes; forgetting to reset the notebook between test cases; overflow when counts grow (use `long` or a modulus).
--cost
Time is the number of distinct states times the work per state, here O(n times number of step sizes). Space O(n) for the notebook plus O(n) recursion depth.
--java
static long ways(int n, int[] steps) {
    long[] memo = new long[n + 1];
    Arrays.fill(memo, -1);                       // -1 means "not computed yet"
    return waysRec(n, steps, memo);
}
static long waysRec(int n, int[] steps, long[] memo) {
    if (n == 0) return 1;                        // base: one way to finish
    if (memo[n] != -1) return memo[n];           // already known
    long total = 0;
    for (int s : steps)
        if (s <= n) total += waysRec(n - s, steps, memo);
    return memo[n] = total;                      // write it in the notebook
}
--py
def ways(n, steps):
    memo = {}                                    # the notebook
    def f(k):
        if k == 0:
            return 1                             # base: one way to finish
        if k in memo:
            return memo[k]                       # already known
        memo[k] = sum(f(k - s) for s in steps if s <= k)
        return memo[k]
    return f(n)
--cpp
long long waysRec(int n, const vector<int>& steps, vector<long long>& memo) {
    if (n == 0) return 1;                        // base: one way to finish
    if (memo[n] != -1) return memo[n];           // already known
    long long total = 0;
    for (int s : steps)
        if (s <= n) total += waysRec(n - s, steps, memo);
    return memo[n] = total;                      // write it in the notebook
}
long long ways(int n, const vector<int>& steps) {
    vector<long long> memo(n + 1, -1);           // -1 means "not computed yet"
    return waysRec(n, steps, memo);
}

### dp1
--idea
One-dimensional DP means the state is a single index, usually a position in a list, and the answer at that position is built from answers at earlier positions. The picture is a row of boxes. You fill them left to right, and each box is computed from boxes you already filled.
We use the maximum subarray sum as the example: the largest total of a run of consecutive numbers. The one insight: the best run that ends at position `i` is either the number alone, or the best run ending at `i - 1` extended by this number. A run ending at `i` never needs to look further back than `i - 1`.
--build
1. State: `best[i]` is the largest sum of a run of consecutive numbers that ends exactly at position `i` (the run must include `a[i]`).
2. Transition: `best[i] = a[i] + max(0, best[i - 1])`. If the best run before is negative, drop it and start fresh at `i`.
3. Base case: `best[0] = a[0]`.
4. Order to fill: `i` from 0 up to `n - 1`, because each box needs the one to its left.
5. Read the answer: the run can end anywhere, so the answer is the maximum of all `best[i]`, not just the last one. Step 5 calls the code piece `chmax` to keep the running maximum.
6. Memory: only `best[i - 1]` is needed, so keep one variable `cur` and one variable `ans`.
--think
- Signal: "best over a sequence" where a good answer at `i` can be built from the answer at `i - 1` (or a few earlier). Often the problem says "ending at", "consecutive", "contiguous", or "up to position".
- The first decision is what the state means. Nearly every mistake comes from a state that does not say whether position `i` is included. Say it in a sentence: "ends exactly at `i`".
- Because the state says "ends exactly at `i`", the final answer is a scan over all states. When the state says "best within the first `i`", the answer is the last state.
- Neighbours: if the transition needs a range of earlier states, see DP with prefix sums or the monotonic queue DP. If you choose items under a limit, see knapsack. If two sequences are involved, see the two-sequence DP.
- Memory shrink: when `dp[i]` uses only the last `k` entries, keep `k` variables.
- Pitfalls: starting `ans` at 0 when all numbers are negative (the answer is then the largest single number, so start at `a[0]`); using `int` when the sum can exceed about two billion.
--cost
Time O(n). Space O(1) with the two-variable form.
--java
static long maxSubarray(int[] a) {
    long cur = a[0];
    long[] best = {a[0]};                        // best[0] = answer so far
    for (int i = 1; i < a.length; i++) {
        cur = a[i] + Math.max(0, cur);           // extend, or start fresh
        chmax(best, 0, cur);                     // the run may end anywhere
    }
    return best[0];
}
--py
def max_subarray(a):
    cur = a[0]
    best = [a[0]]                                # best[0] = answer so far
    for x in a[1:]:
        cur = x + max(0, cur)                    # extend, or start fresh
        chmax(best, 0, cur)                      # the run may end anywhere
    return best[0]
--cpp
long long maxSubarray(const vector<int>& a) {
    long long cur = a[0], ans = a[0];
    for (size_t i = 1; i < a.size(); i++) {
        cur = a[i] + max(0LL, cur);              // extend, or start fresh
        chmax(ans, cur);                         // the run may end anywhere
    }
    return ans;
}

### coin
--idea
Coin change asks for the fewest coins that add up to a target amount, given coin values you can use any number of times. Greedy (always take the biggest coin) fails for values like 1, 3, 4 and target 6: greedy gives 4+1+1 (three coins), but 3+3 needs two.
The insight: the last coin you add to reach amount `x` is some coin `c`, and before it you had amount `x - c` using as few coins as possible. So try every coin as the last one and keep the best.
--build
1. State: `dp[x]` is the fewest coins needed to make exactly amount `x`, or infinity if it cannot be made.
2. Transition: `dp[x] = 1 + min(dp[x - c])` over every coin `c` with `c <= x`.
3. Base case: `dp[0] = 0` (zero coins make zero). All other entries start at infinity (use `target + 1`, which no real answer can reach).
4. Order to fill: `x` from 1 to `target`. Each update calls the code pieces `safeAdd` (adding to INF stays INF) and `chmin` (keep the smaller value). Each `x` needs only smaller amounts.
5. Read the answer: `dp[target]`. If it is still infinity, return -1.
--think
- Signal: "fewest", "minimum number of", pieces from a set with unlimited reuse, exact total. If each item can be used once, it is the 0/1 knapsack; if you must count ways instead, see coin change count ways.
- Choose the state as the remaining amount. The history of coins does not matter, only the sum.
- Why not greedy: greedy works only for special coin systems (like 1, 5, 10, 25). When in doubt, use DP.
- Memory is already O(target). Time is O(target times coins); if the target is huge but coins are few and small, think shortest path with the amounts modulo the smallest coin.
- Pitfalls: using `Integer.MAX_VALUE` as infinity and then adding 1 (overflow); forgetting the answer can be impossible; confusing "fewest coins" (min) with "number of ways" (sum).
--cost
Time O(target times number of coins). Space O(target).
--java
static int coinChange(int[] coins, int target) {
    long[] dp = new long[target + 1];
    Arrays.fill(dp, INF);                        // INF from the code piece u-inf
    dp[0] = 0;                                   // zero coins make zero
    for (int x = 1; x <= target; x++)
        for (int c : coins)
            if (c <= x) chmin(dp, x, safeAdd((int) dp[x - c], 1));
    return dp[target] >= INF ? -1 : (int) dp[target];
}
--py
def coin_change(coins, target):
    dp = [INF] * (target + 1)                    # INF from the code piece u-inf
    dp[0] = 0                                    # zero coins make zero
    for x in range(1, target + 1):
        for c in coins:
            if c <= x:
                chmin(dp, x, safe_add(dp[x - c], 1))
    return -1 if dp[target] == INF else dp[target]
--cpp
int coinChange(const vector<int>& coins, int target) {
    vector<int> dp(target + 1, INF);             // INF from the code piece u-inf
    dp[0] = 0;                                   // zero coins make zero
    for (int x = 1; x <= target; x++)
        for (int c : coins)
            if (c <= x) chmin(dp[x], safeAdd(dp[x - c], 1));
    return dp[target] >= INF ? -1 : dp[target];
}

### coinways
--idea
Count the ways (modulo 1,000,000,007, since counts grow huge) to make a target amount from coin values you can reuse. Two ways are the same if they use the same number of each coin, so 1+2 and 2+1 count once. This is "combinations", not "ordered sequences".
The trick is the loop order. If you loop over coins on the outside and amounts on the inside, each coin is introduced once, in a fixed order, so every combination is counted exactly one time. Swap the loops and you count ordered sequences instead (the memoization lesson's stairs count).
--build
1. State: `dp[x]` is the number of combinations of the coins processed so far that add up to exactly `x`.
2. Transition: when you process coin `c`, for every `x` from `c` up to `target`, do `dp[x] = addMod(dp[x], dp[x - c], M)` with `M = 1,000,000,007`. The addition is the code piece `addMod`, so counts stay small. This means "any combination for `x - c`, plus one more coin `c`".
3. Base case: `dp[0] = 1` (the empty combination), every other entry 0.
4. Order to fill: coins on the outside loop, in any fixed order. For each coin, amounts go upward, so a coin can be reused.
5. Read the answer: `dp[target]` after all coins are processed.
--think
- Signal: "number of ways", "how many combinations", order does not matter, items are reusable. If order matters, put amounts outside and coins inside.
- A useful check: with coins 1 and 2 and target 3, combinations are {1,1,1} and {1,2}, so 2. Ordered sequences would be 3.
- The state is only the amount, because the loop order already guarantees we never use a smaller coin after a larger one.
- Counts grow fast. Problems usually ask for the answer modulo a number (for example 1,000,000,007). Take the modulus after every addition.
- Neighbours: coin change (fewest) uses min, unbounded knapsack uses max, 0/1 counting loops amounts downward.
- Pitfalls: swapping the two loops; forgetting `dp[0] = 1`; overflow without a modulus.
--cost
Time O(target times number of coins). Space O(target).
--java
static int coinWays(int[] coins, int target) {
    final int M = 1_000_000_007;
    int[] dp = new int[target + 1];
    dp[0] = 1;                                   // the empty combination
    for (int c : coins)                          // coins outside: no double counting
        for (int x = c; x <= target; x++)
            dp[x] = addMod(dp[x], dp[x - c], M); // upward: coin reusable
    return dp[target];
}
--py
def coin_ways(coins, target):
    M = 1_000_000_007
    dp = [0] * (target + 1)
    dp[0] = 1                                    # the empty combination
    for c in coins:                              # coins outside: no double counting
        for x in range(c, target + 1):
            dp[x] = add_mod(dp[x], dp[x - c], M) # upward: coin reusable
    return dp[target]
--cpp
int coinWays(const vector<int>& coins, int target) {
    const int M = 1000000007;
    vector<int> dp(target + 1, 0);
    dp[0] = 1;                                   // the empty combination
    for (int c : coins)                          // coins outside: no double counting
        for (int x = c; x <= target; x++)
            dp[x] = addMod(dp[x], dp[x - c], M); // upward: coin reusable
    return dp[target];
}

### houserob
--idea
A row of houses each holds some money. You may take from any set of houses as long as no two are next to each other (the alarm rings). Find the largest total. The same pattern shows up whenever choosing an item forbids its neighbours.
At each house you have two options: skip it (keep the best from the houses before), or take it (its money plus the best from the houses before the previous one). Pick the larger.
--build
1. State: `dp[i]` is the best total using only the first `i` houses (houses numbered 1 to `i`).
2. Transition: `dp[i] = max(dp[i - 1], dp[i - 2] + a[i])`. Skip house `i`, or take it and jump over house `i - 1`.
3. Base case: `dp[0] = 0` (no houses), `dp[1] = a[1]`. You can treat `dp[-1]` as 0 to unify.
4. Order to fill: `i` from 1 to `n`.
5. Read the answer: `dp[n]`, because the state already says "using the first `i` houses", so the last one covers all choices.
6. The code writes the take option with the code piece `chmax` (keep the larger). Memory: only the last two values are needed, so `dp` can shrink to two variables.
--think
- Signal: pick items from a line, picking one blocks its neighbours; or "no two adjacent". Variants: houses in a circle (run it twice, once without the first house and once without the last), or forbid neighbours within distance `k` (then the transition looks back `k` steps).
- The state "first `i` houses" differs from "ending at `i`". Here the first is easier: you take the max with skipping, so the last state holds the final answer.
- Neighbours: for values that need 2D "take or skip with counts", see knapsack; for a tree instead of a line (no parent and child both), see tree DP; to delete numbers with equal value together ("delete and earn"), reduce it to this by grouping equal values.
- Pitfalls: negative values (the empty choice gives 0, which this recurrence already allows); the circle case with one house; mixing `i - 2` indexes with 0-based arrays.
--cost
Time O(n). Space O(1).
--java
static long rob(int[] a) {
    int n = a.length;
    long[] dp = new long[n + 1];                 // dp[i]: best using the first i houses
    for (int i = 1; i <= n; i++) {
        dp[i] = dp[i - 1];                       // skip house i
        chmax(dp, i, (i >= 2 ? dp[i - 2] : 0) + a[i - 1]);   // or take it
    }
    return dp[n];
}
--py
def rob(a):

    for i in range(1, n + 1):
        dp[i] = dp[i - 1]                        # skip house i
        chmax(dp, i, (dp[i - 2] if i >= 2 else 0) + a[i - 1])   # or take it
    return dp[n]
--cpp
long long rob(const vector<int>& a) {
    int n = a.size();
    vector<long long> dp(n + 1, 0);              // dp[i]: best using the first i houses
    for (int i = 1; i <= n; i++) {
        dp[i] = dp[i - 1];                       // skip house i

    }
    return dp[n];
}

### dp2
--idea
Two-dimensional DP keeps answers in a table with two indexes, for example a row and a column of a grid. Each cell is filled from cells above it, to its left, or both. The picture: you sweep the grid row by row, and each cell asks its already-filled neighbours.
The example here is the largest square made of 1s inside a grid of 0s and 1s. A square whose bottom-right corner is at a cell can only be as big as the smallest of the three squares ending at the cell above, the cell to the left, and the cell diagonally up-left, plus one. A zero blocks it completely.
--build
1. State: `dp[i][j]` is the side length of the largest all-1 square whose bottom-right corner is exactly cell `(i, j)`.
2. Transition: if `g[i][j] = 1` then `dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])`, else `dp[i][j] = 0`.
3. Base case: cells outside the grid count as 0, so for row 0 or column 0 the value is just `g[i][j]` (1 or 0). Use a table padded with one extra zero row and column to avoid special cases. The code builds each row with the code piece `newTable(m, 0)`, which gives `m + 1` zeros.
4. Order to fill: row by row, left to right, so the three neighbours are filled first.
5. Read the answer: the square can end at any corner, so take the maximum `dp[i][j]` over the whole grid, and return its side length (the area is the square of it).
6. Memory: each row needs only the previous row, so two rows are enough.
--think
- Signal: a grid, and a question about shapes that can be grown from smaller shapes ending at a corner, or a value per cell depending on its neighbours above and left.
- Decide the state as "answer for the structure ending at this cell". Writing the three neighbours' meaning down in words proves the min formula.
- Neighbours: minimum path sum and counting paths use the same table with a different transition; two-sequence DP uses the table with rows and columns being prefixes of two strings.
- Shrink memory to one or two rows when each cell needs only the previous row and the cell to its left. Be careful: if you update one row in place, save the old diagonal value before overwriting it.
- Pitfalls: mixing up `dp[i][j]` meaning "ends here" with "best so far" (then the answer is the grid maximum, not the last cell); off-by-one at the border; reading the grid as rows by columns the wrong way round.
--cost
Time O(rows times columns). Space O(columns) with the rolling row form, O(rows times columns) for the full table.
--java
static long largestSquare(int[][] g) {
    int n = g.length, m = g[0].length;
    long best = 0;
    long[][] dp = new long[n + 1][];
    for (int i = 0; i <= n; i++) dp[i] = newTable(m, 0);   // padded with zeros
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            if (g[i - 1][j - 1] == 1) {
                dp[i][j] = 1 + Math.min(dp[i - 1][j], Math.min(dp[i][j - 1], dp[i - 1][j - 1]));
                best = Math.max(best, dp[i][j]);
            }
    return best * best;                          // area of the biggest square
}
--py

### minpath
--idea
You walk from the top-left of a grid of costs to the bottom-right, moving only right or down, and pay the cost of every cell you step on. Find the cheapest total. Every route enters a cell from above or from the left, so the cheapest route to a cell is its own cost plus the cheaper of those two.
The insight is that the cheapest route to a cell does not care how it got to the previous cell, only how cheap that was. So the problem splits into smaller identical problems.
--build
1. State: `dp[i][j]` is the minimum cost of a route from `(0, 0)` to cell `(i, j)`, including the cost of both end cells.
2. Transition: `dp[i][j] = g[i][j] + min(dp[i-1][j], dp[i][j-1])`, using only the neighbours that exist.
3. Base case: `dp[0][0] = g[0][0]`. The first row can only come from the left, the first column only from above.
4. Order to fill: row by row, left to right.
5. Read the answer: `dp[n-1][m-1]`.
6. The code makes its row with the code piece `newTable(m, 0)` (one spare entry at the end). Memory: one row `dp[j]` is enough. Updating in place: `dp[j] = g[i][j] + min(dp[j], dp[j-1])`, where `dp[j]` before the update is the value from above.
--think
- Signal: grid, restricted directions (right and down), minimise or maximise a sum. If you may move in all four directions, the table order breaks and you need Dijkstra (shortest path with non-negative costs) instead.
- Variants: maximum path sum (swap `min` for `max`), obstacles (set blocked cells to infinity), a triangle (same idea with a shorter row), two walkers at once (add a state for the second walker).
- Recover the actual route by walking back from the end, at each cell going to the neighbour that gave the min.
- Pitfalls: the first row and column need their own handling; using infinity for the missing neighbour and then adding to it (use a large but safe number); swapping the row and column bounds when the grid is not square.
--cost
Time O(rows times columns). Space O(columns) with one rolling row.
--java
static long minPath(int[][] g) {
    int n = g.length, m = g[0].length;
    long[] dp = newTable(m, 0);                  // one row
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++) {
            if (i == 0 && j == 0) dp[j] = g[0][0];
            else if (i == 0) dp[j] = dp[j - 1] + g[i][j];         // only from the left
            else if (j == 0) dp[j] = dp[j] + g[i][j];             // only from above
            else dp[j] = Math.min(dp[j], dp[j - 1]) + g[i][j];    // dp[j] is "above"
        }
    return dp[m - 1];
}

### lcs
--idea
The longest common subsequence (LCS) of two strings is the longest sequence of characters that appears in both, in the same order but not necessarily next to each other. For "ABCBDAB" and "BDCABA", one answer is "BCBA", length 4. Think of it as lining the two strings up and drawing non-crossing lines between equal letters.
Look at the last characters. If they are equal, they can be matched, and you are left with the same problem on the strings without them. If not, at least one of them is unused, so drop one or the other and take the better result.
--build
1. State: `dp[i][j]` is the LCS length of the first `i` characters of `a` and the first `j` characters of `b`.
2. Transition: if `a[i-1] == b[j-1]` then `dp[i][j] = dp[i-1][j-1] + 1`, else `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.
3. Base case: `dp[0][j] = 0` and `dp[i][0] = 0`, because an empty string shares nothing.
4. The table rows come from the code piece `newTable(m, 0)`, and the max in the mismatch case is the code piece `chmax`. Order to fill: `i` from 1 to `n`, `j` from 1 to `m`. Each cell needs the cell above, left, and diagonal.
5. Read the answer: `dp[n][m]`.
6. To rebuild the string, walk back from `(n, m)`: on a match step diagonally and keep the letter, otherwise step towards the larger neighbour.
--think
- Signal: two sequences, "in order", "subsequence", "common", "edit", "align". Rows are prefixes of one sequence, columns prefixes of the other. If the word is "substring" (contiguous), the transition resets to 0 on a mismatch and the answer is the table maximum.
- Neighbours: edit distance and distinct subsequences have the same table; longest palindromic subsequence is LCS of a string and its reverse; longest increasing subsequence can be done as LCS with the sorted copy (but use the n log n method).
- Memory: keep only two rows, or one row plus a saved diagonal. If you must rebuild the string, you need the full table (or divide and conquer, Hirschberg).
- Pitfalls: indexing the strings with `i` instead of `i - 1`; forgetting that on a match you do not need the max (matching is never worse); table dimensions `(n + 1) times (m + 1)`.
--cost
Time O(n times m). Space O(m) for the length only, O(n times m) to rebuild the string.
--java
static int lcs(String a, String b) {
    int n = a.length(), m = b.length();
    long[][] dp = new long[n + 1][];
    for (int i = 0; i <= n; i++) dp[i] = newTable(m, 0);   // row 0 and column 0 stay 0
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            if (a.charAt(i - 1) == b.charAt(j - 1))
                dp[i][j] = dp[i - 1][j - 1] + 1;           // match them
            else {
                dp[i][j] = dp[i - 1][j];                   // drop a letter of a
                chmax(dp[i], j, dp[i][j - 1]);             // or a letter of b
            }
    return (int) dp[n][m];
}

### editdist
--idea
Edit distance (also called Levenshtein distance) is the fewest single-character edits needed to turn one string into another. An edit is an insert, a delete, or a replace of one character. It measures how different two words are, and powers spell checkers and diff tools.
Look at the ends of the two prefixes. If the last letters are equal, they cost nothing and you solve the shorter problem. If not, the last operation was one of three edits, each leaving a smaller problem, so take the cheapest of the three.
--build
1. State: `dp[i][j]` is the fewest edits to turn the first `i` characters of `a` into the first `j` characters of `b`.
2. Transition: if `a[i-1] == b[j-1]` then `dp[i][j] = dp[i-1][j-1]`. Otherwise `dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])`. These three are: delete from `a`, insert into `a`, and replace.
3. Base case: `dp[i][0] = i` (delete all `i` letters) and `dp[0][j] = j` (insert all `j` letters).
4. Rows come from the code piece `newTable(m, 0)`; the best of the three edits is kept with the code piece `chmin`. Order to fill: `i` from 1 to `n`, `j` from 1 to `m`.
5. Read the answer: `dp[n][m]`.
6. To list the edits, walk back from `(n, m)` and follow whichever neighbour produced the value.
--think
- Signal: "minimum number of operations to transform", "similarity", "closest match". Each allowed operation maps to one move in the table: delete moves up, insert moves left, replace moves diagonally.
- The state is a pair of prefix lengths. Different costs per operation just change the constants in the min. If only inserts and deletes are allowed, the distance is `n + m - 2 * LCS`.
- Neighbours: LCS (the same table, different transition); wildcard matching; distinct subsequences. For a very long string with a small allowed distance `k`, only cells near the diagonal matter, which gives O(n times k).
- Pitfalls: forgetting the base row and column (they are not 0); writing `+1` on the match branch; swapping insert and delete roles (harmless for the count, but matters when you list edits).
--cost
Time O(n times m). Space O(m) with two rows, O(n times m) if you need the list of edits.
--java
static int editDistance(String a, String b) {
    int n = a.length(), m = b.length();
    long[][] dp = new long[n + 1][];
    for (int i = 0; i <= n; i++) dp[i] = newTable(m, 0);
    for (int i = 0; i <= n; i++) dp[i][0] = i;   // delete everything
    for (int j = 0; j <= m; j++) dp[0][j] = j;   // insert everything
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            if (a.charAt(i - 1) == b.charAt(j - 1))
                dp[i][j] = dp[i - 1][j - 1];               // free match
            else {
                dp[i][j] = 1 + dp[i - 1][j - 1];           // replace
                chmin(dp[i], j, 1 + dp[i - 1][j]);         // delete
                chmin(dp[i], j, 1 + dp[i][j - 1]);         // insert
            }
    return (int) dp[n][m];
}

### lps
--idea
A subsequence keeps the original order but may skip characters. The longest palindromic subsequence (LPS) is the longest subsequence that reads the same forwards and backwards. In "BBABCBCAB" it is "BABCBAB", length 7. Unlike a substring, the letters need not be adjacent.
Look at the two ends of a range. If they are equal, both belong to the palindrome and you shrink to the inside. If not, one of them is not used, so drop either end and take the better.
--build
1. State: `dp[i][j]` is the length of the longest palindromic subsequence inside `s[i..j]` (both ends inclusive).
2. Transition: if `s[i] == s[j]` then `dp[i][j] = dp[i+1][j-1] + 2`, else `dp[i][j] = max(dp[i+1][j], dp[i][j-1])`.
3. Base case: `dp[i][i] = 1` (one letter). An empty range, `i > j`, is 0 (this matters for `dp[i+1][j-1]` when `j = i + 1`).
4. Rows come from the code piece `newTable(n - 1, 0)` (n zeros), and the better end to drop is kept with the code piece `chmax`. Order to fill: ranges by growing length, or `i` from `n - 1` down to 0 with `j` from `i + 1` up to `n - 1`. Both make sure the smaller ranges are done first.
5. Read the answer: `dp[0][n-1]`.
--think
- Signal: palindrome, but with deletions allowed ("fewest deletions to make a palindrome" is `n` minus this value). The state is a range, so this is interval DP (answers for ranges built from smaller ranges).
- Shortcut: the LPS of `s` equals the LCS of `s` and its reverse. Use whichever you find easier to get right.
- If the question asks about contiguous pieces (substrings), use the palindromic substrings table instead.
- Memory can be cut to one row if you fill `i` downward and keep the previous diagonal in a variable.
- Pitfalls: filling in the wrong order so `dp[i+1][j-1]` is not ready; forgetting the empty-range 0 for adjacent equal letters (`"aa"` must give 2); using the same index range check for strings of length 0.
--cost
Time O(n squared). Space O(n squared), or O(n) with the rolling row.
--java
static int lps(String s) {
    int n = s.length();
    if (n == 0) return 0;
    long[][] dp = new long[n][];
    for (int i = 0; i < n; i++) dp[i] = newTable(n - 1, 0);   // empty ranges stay 0
    for (int i = n - 1; i >= 0; i--) {
        dp[i][i] = 1;                            // a single letter
        for (int j = i + 1; j < n; j++)
            if (s.charAt(i) == s.charAt(j))
                dp[i][j] = dp[i + 1][j - 1] + 2;           // both ends used
            else {
                dp[i][j] = dp[i + 1][j];                   // drop the left end
                chmax(dp[i], j, dp[i][j - 1]);             // or the right end
            }
    }
    return (int) dp[0][n - 1];
}

### palindp
--idea
A palindromic substring is a block of consecutive characters that reads the same both ways. To count or find them all, mark which ranges `[i, j]` are palindromes. A range is a palindrome when its two end letters match and the range inside them is also a palindrome. This is the same picture as peeling a mirror from the outside in.
A table of true and false answers for all ranges turns a check that would cost O(n) per range into O(1), because the inside range is shorter and already known.
--build
1. State: `ok[i][j]` is true when the substring `s[i..j]` (inclusive) is a palindrome.
2. Transition: `ok[i][j] = (s[i] == s[j]) and (j - i < 2 or ok[i+1][j-1])`. Lengths 1 and 2 need no inner check.
3. Base case: every single letter `ok[i][i]` is true. Length 2 is true when both letters are equal.
4. Order to fill: `i` from `n - 1` down to 0, and `j` from `i` up to `n - 1`, so `ok[i+1][j-1]` is ready.
5. Read the answer: the number of true cells is the count of palindromic substrings. To get the longest, remember the widest true `[i, j]`.
--think
- Signal: palindromes that are contiguous and you need counts, the longest one, or a minimum number of cuts to split a string into palindromes (use `ok` inside a second 1D DP: `cut[j] = min(cut[i-1] + 1)` over `i` with `ok[i][j]`).
- Alternative for count or longest only: expand around each of the 2n - 1 centres, which is O(n squared) time and O(1) memory. Manacher's algorithm does it in O(n). Use the table when other DPs need random access to `ok`.
- Neighbours: longest palindromic subsequence (not contiguous), interval DP in general.
- Pitfalls: counting each substring once per start and end (the table already does that, but equal substrings at different places each count); the `j - i < 2` guard, without which you read outside the table; wrong loop order.
--cost
Time O(n squared). Space O(n squared).
--java
static int countPalindromes(String s) {
    int n = s.length(), count = 0;
    boolean[][] ok = new boolean[n][n];
    for (int i = n - 1; i >= 0; i--)
        for (int j = i; j < n; j++)
            if (s.charAt(i) == s.charAt(j) && (j - i < 2 || ok[i + 1][j - 1])) {
                ok[i][j] = true;                 // ends match, inside is a palindrome
                count++;
            }
    return count;
}
--py

### unbounded
--idea
The unbounded knapsack is the knapsack where every item can be taken as many times as you like (think of a shop with unlimited stock). You have a bag of limited weight and want the most total value. The 0/1 version lets you take each item once; here the supply never runs out.
The only change from 0/1 knapsack is the direction of the capacity loop. Going upward lets `dp[c - w]` already include the current item, so the item can be added again. Going downward forbids that. The whole difference between the two problems is one loop direction.
--build
1. State: `dp[c]` is the best total value for a bag of capacity exactly `c` or less, using any of the items any number of times.
2. Transition: for each item `(w, v)` and each `c >= w`, `dp[c] = max(dp[c], dp[c - w] + v)`. It means "the best for the smaller bag, plus one more copy of this item".
3. Base case: `dp[0] = 0` and, since leftover room is allowed, all entries start at 0.
4. Order to fill: item by item, and for each item `c` goes upward from `w` to `cap`. Upward is what lets an item be reused.
5. Read the answer: `dp[cap]`.
6. If the bag must be filled exactly, start with `dp[0] = 0` and all others at minus infinity, and read `dp[cap]`.
--think
- Signal: "unlimited supply", "any number of times", cutting a rod into pieces for the best price, coin problems that maximise value.
- Contrast with 0/1 knapsack: ask "may I use an item twice?" If yes, loop capacity upward. If no, downward. Write it in a comment.
- With many items sharing the same weight, keep only the best value for that weight.
- If weights are huge but values small, flip the DP: let the state be the value and store the least weight.
- A greedy by value density (value per weight) is only a guess, not an exact method, unless the problem allows fractions.
- Pitfalls: using the downward loop by habit; forgetting a weight of 0 with positive value (infinite value); filling "exactly" versus "at most".
--cost
Time O(items times cap). Space O(cap).
--java
static long unboundedKnapsack(int[] w, int[] v, int cap) {
    long[] dp = new long[cap + 1];               // at most c: all start at 0
    for (int i = 0; i < w.length; i++)
        for (int c = w[i]; c <= cap; c++)        // upward: item can repeat
            dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
    return dp[cap];
}
--py
def unbounded_knapsack(w, v, cap):
    dp = [0] * (cap + 1)                         # at most c: all start at 0
    for i in range(len(w)):
        for c in range(w[i], cap + 1):           # upward: item can repeat
            dp[c] = max(dp[c], dp[c - w[i]] + v[i])
    return dp[cap]
--cpp

    vector<long long> dp(cap + 1, 0);            // at most c: all start at 0
    for (size_t i = 0; i < w.size(); i++)
        for (int c = w[i]; c <= cap; c++)        // upward: item can repeat
            dp[c] = max(dp[c], dp[c - w[i]] + v[i]);
    return dp[cap];
}

### subsetsum
--idea
Subset sum asks: given some numbers, can you pick some of them (each at most once) that add up to exactly a target? Picture a row of switches, each adding its number to a running total when on. You want to know if the total can land exactly on the target.
It is a knapsack in disguise: treat every number as an item whose value equals its weight. Then the best value for a bag of size `target` is the largest total not above `target` that some subset can make, and the target is buildable exactly when that best value equals the target.
--build
1. State: `best[c]` is the largest total that is at most `c` and can be made by some subset of the numbers processed so far.
2. Transition: for each number `x`, for `c` from `target` down to `x`: `best[c] = max(best[c], best[c - x] + x)`. In words: skip `x`, or take it on top of the best for the smaller bag.
3. Base case: every `best[c]` starts at 0 (the empty subset makes 0).
4. Order to fill: numbers one at a time; for each number, `c` goes downward so `x` is used at most once.
5. Read the answer: the target can be built exactly when `best[target] == target`.
6. This loop is exactly the code piece `knapsack` (one rolling row), so the code calls `knapsack(a, a, target)`: the numbers are used as both weights and values. To list the subset, keep the full table by number and walk back.
--think
- Signal: "can we make exactly", "is there a subset", "split into two equal halves", partition. Sums must be small enough to hold in an array (up to a few million). Negative numbers need an offset, or a map.
- If the target is huge but there are few numbers (about 40), meet in the middle: enumerate subset sums of each half and match them with sorting or a hash set.
- Speed-up: pack the true/false array in bits and do `bits |= bits << x` (knapsack with bitsets), which is about 64 times faster.
- To count subsets, change `or` to `+`. For the fewest numbers used, change to `min`.
- Pitfalls: upward loop (reuses a number, which is the unbounded version); the target is zero; numbers bigger than the target should be skipped; target larger than the total.
--cost
Time O(n times target). Space O(target).
--java
static boolean subsetSum(int[] a, int target) {
    // numbers as both weights and values: best total <= target, via the knapsack piece
    return knapsack(a, a, target) == target;
}
--py
def subset_sum(a, target):
    # numbers as both weights and values: best total <= target, via the knapsack piece
    return knapsack(a, a, target) == target
--cpp
bool subsetSum(const vector<int>& a, int target) {
    // numbers as both weights and values: best total <= target, via the knapsack piece
    return knapsack(a, a, target) == target;
}

### partition
--idea
Partition problems split a set of numbers into two groups so that the sums are as balanced as possible, or exactly equal. Say the numbers total `T`. If one group sums to `s`, the other sums to `T - s`, and the gap is `T - 2s`. So you only need to know which `s` values can be built, and pick the one closest to `T / 2`.
That turns a splitting problem into subset sum: find every reachable `s` up to `T / 2`, then take the biggest. The smallest possible difference is `T - 2 * best`.
--build
1. Compute `T`, the total of all numbers. Let `half = T / 2` (integer division).
2. State: `best[c]` is the largest group sum that is at most `c` and can be made from some of the numbers processed so far.
3. Transition: for each number `x`, for `c` from `half` down to `x`: `best[c] = max(best[c], best[c - x] + x)`.
4. Base case: every `best[c]` is 0 at the start.
5. Order to fill: numbers outside, `c` downward.
6. Read the answer: `best[half]` is the biggest group sum not above `half`, call it `s`. The minimum difference is `T - 2 * s`. For "split into two equal halves", check `T - 2 * s == 0`.
7. Steps 2 to 5 are the code piece `knapsack` with each number used as both weight and value, so the code calls `knapsack(a, a, half)`.
--think
- Signal: "divide into two groups", "minimise the difference", "balance", "equal sum partition". The whole thing is subset sum in disguise.
- Only half the total needs to be searched because the other group is the leftover.
- With signs: "assign + or - to each number to reach a target" has `P - N = target` and `P + N = T`, so `P = (T + target) / 2`, then count subsets with sum `P` (parity and range checks first).
- More than two groups (for example three equal groups) is harder: use a bitmask DP over subsets, or backtracking.
- Pitfalls: odd total for the equal case; picking the smallest `s` instead of the largest `s <= half`; sums too big for the array (then use a bitset or meet in the middle).
--cost
Time O(n times T). Space O(T).
--java
static int minDifference(int[] a) {
    int total = 0;
    for (int x : a) total += x;
    long s = knapsack(a, a, total / 2);          // best group sum not above half
    return (int) (total - 2 * s);
}
--py
def min_difference(a):
    total = sum(a)
    s = knapsack(a, a, total // 2)               # best group sum not above half
    return total - 2 * s
--cpp

### statem
--idea
State machine DP is for problems where, besides the position, you are in one of a few modes, and the rules say which mode can follow which. Think of a small diagram of boxes (modes) with arrows (allowed moves). At each step you ask: "what is the best total if I end this step in mode `m`?"
The example is painting a row of houses with three colours so that neighbours differ, at the least total cost. The mode is the colour of the house just painted. The rule "no same colour next to each other" is the arrow set: from colour `c` you may only go to the other two.
--build
1. List the modes. Here: colour 0, 1 or 2 for the last house painted.
2. State: `dp[i][m]` is the least cost to paint houses `0..i` such that house `i` has colour `m`.
3. Transition: `dp[i][m] = cost[i][m] + min(dp[i-1][k])` over all modes `k != m` (the allowed previous modes).
4. Base case: `dp[0][m] = cost[0][m]` for every mode.
5. Order to fill: `i` from 1 up to `n - 1`. Each row needs only the previous row, so keep three numbers.
6. Read the answer: `min(dp[n-1][m])` over all modes, since the last house may have any colour.
--think
- Signal: a decision per step with a memory of "what I did last" (a colour, holding or not holding, cooldown, a streak length). If a rule mentions the previous or last few steps, the memory is the mode.
- Choose the smallest set of modes that makes the rule checkable. For "no three in a row", the mode is the current streak (0, 1, 2). For "cooldown after a sale", the modes are holding, just sold, and resting.
- Draw the diagram first, then write one line per arrow into the transition.
- Neighbours: stock trading DP is a state machine with modes holding and not holding; 1D DP is the machine with one mode; digit DP adds modes like "already smaller than the limit".
- Pitfalls: forgetting the final min over all modes; using in-place updates that overwrite a mode you still need (use fresh variables for the new row); an impossible mode needs infinity, not 0.
--cost
Time O(n times modes squared). Space O(modes) with rolling values.
--java
static int paintHouses(int[][] cost) {
    int a = cost[0][0], b = cost[0][1], c = cost[0][2];   // best ending in each colour
    for (int i = 1; i < cost.length; i++) {
        int na = cost[i][0] + Math.min(b, c);    // colour 0 now: previous was 1 or 2
        int nb = cost[i][1] + Math.min(a, c);
        int nc = cost[i][2] + Math.min(a, b);
        a = na; b = nb; c = nc;
    }
    return Math.min(a, Math.min(b, c));
}

### stock
--idea
Stock trading DP finds the best profit from a list of daily prices when you may buy and sell under rules, for example "at most `k` trades" (a trade is one buy followed by one sell), and you can hold only one share at a time. It is a state machine: each day you are either holding a share or not.
For each number of trades used so far, track two values: the best money if you hold a share, and the best money if you do not. Each day either do nothing, or switch mode (buy or sell). Selling completes a trade.
--build
1. State: `hold[j]` is the best money after today, having started `j` trades, currently holding a share. `free[j]` is the best money after today, having completed `j` trades, holding nothing.
2. Transition each day with price `p`, for `j` from 1 to `k`: `hold[j] = max(hold[j], free[j-1] - p)` (buy today, starting trade `j`), and `free[j] = max(free[j], hold[j] + p)` (sell today, completing trade `j`).
3. Base case: `free[0] = 0`, `hold[j] = minus infinity` and `free[j] = 0` for `j >= 1` (doing nothing is always possible).
4. The two `max` updates are calls to the code piece `chmax`, and "not holding anything yet" is minus the code piece constant `INF`. Order to fill: days from first to last. Within a day, update `hold[j]` before `free[j]` so a buy and sell on the same day gives zero profit, which is harmless.
5. Read the answer: `free[k]`, since more trades can never hurt (a trade may have profit zero).
6. Shortcut: if `k >= n / 2`, trades are effectively unlimited, so set `k = n / 2` to bound the work.
--think
- Signal: stock prices with limits (one trade, `k` trades, cooldown, a fee per trade, unlimited trades). Each rule adds a mode or a counter.
- With a fee, subtract it at the sell. With a one-day cooldown after selling, add a mode "cooling" which can only move to free the next day.
- Unlimited trades with no fee has no need for DP: add every positive day-to-day rise.
- Think of it as a state machine DP whose modes are holding or not, crossed with the number of trades.
- Pitfalls: starting `hold` at 0 (it means you got a share for free); counting a buy and a sell as two trades when the limit counts pairs; large `k` making time O(nk) blow up without the clamp.
--cost
Time O(n times k). Space O(k).
--java
static int maxProfit(int k, int[] prices) {
    int n = prices.length;
    k = Math.min(k, n / 2);                      // more trades than this never help
    long[] hold = new long[k + 1], free = new long[k + 1];   // free starts at 0
    Arrays.fill(hold, -INF);                     // not holding anything yet
    for (int p : prices)
        for (int j = 1; j <= k; j++) {
            chmax(hold, j, safeAdd((int) free[j - 1], -p));     // buy: start trade j
            chmax(free, j, hold[j] + p);         // sell: finish trade j
        }
    return k == 0 ? 0 : (int) free[k];
}
--py

### dppref
--idea
Some DP transitions add up a whole range of earlier answers, such as "the sum of `dp[i - m]` through `dp[i - 1]`". Done naively, each one costs O(m). A prefix sum (a running total array, so any range sum is one subtraction) makes each transition O(1).
The example is rolling `n` dice with faces 1 to `m` and counting the ways to total `s`. The number of ways to reach `s` with `i` dice is the sum of the ways to reach `s - 1`, `s - 2`, up to `s - m` with `i - 1` dice, one for each face of the last die.
--build
1. State: `dp[i][s]` is the number of ways to get total exactly `s` using `i` dice, taken modulo `P = 1,000,000,007` so numbers stay small.
2. Transition: `dp[i][s] = dp[i-1][s-1] + dp[i-1][s-2] + ... + dp[i-1][s-m]`, ignoring indexes below 0. This is a range sum over the previous row.
3. Base case: `dp[0][0] = 1` (zero dice, total zero), the rest of row 0 is 0.
4. Speed-up: build `pre[t]` = sum of `dp[i-1][0..t-1]` (taken modulo `P`). Then the window sum is the code piece `rangeSum(pre, max(0, s - m), s - 1)`, which is `pre[s] - pre[max(0, s - m)]`, and a final `% P` (with `+ P` to cancel a negative) fixes the modulus.
5. Order to fill: `i` from 1 to `n`; for each row build the prefix array first and then fill the row.
6. Read the answer: `dp[n][s]`.
--think
- Signal: a transition that sums or minimises over a contiguous window of earlier states. For sums, use prefix sums (works because subtraction undoes addition). For minimums, use a monotonic queue (monotonic queue DP), since min has no subtraction.
- Another form: a difference array. Instead of adding to a range one by one, mark the start and end, then sweep. Use it when the range is "pushed forward" from the current state.
- Always handle the modulus: after subtracting, add `P` and take the remainder again, so the value is never negative.
- Neighbours: counting paths and coin ways use one-term transitions; this lesson is for window transitions.
- Pitfalls: window start below 0; off-by-one between `pre[s]` (sum before `s`) and `pre[s + 1]`; forgetting the modulus on the subtraction; using `int` when adding two values below `P` (sum up to 2 billion can overflow `int` in Java and C++, so use `long`).
--cost
Time O(n times s) instead of O(n times s times m). Space O(s) with two rows.
--java
static long diceWays(int n, int m, int s) {
    final long P = 1_000_000_007L;
    long[] dp = new long[s + 1];
    dp[0] = 1;                                   // zero dice, total 0
    for (int i = 1; i <= n; i++) {
        long[] pre = new long[s + 2];            // pre[t] = dp[0] + ... + dp[t-1]
        for (int t = 0; t <= s; t++) pre[t + 1] = (pre[t] + dp[t]) % P;
        long[] nd = new long[s + 1];
        for (int t = 1; t <= s; t++)             // sum of dp[t-m .. t-1]
            nd[t] = ((rangeSum(pre, Math.max(0, t - m), t - 1) % P) + P) % P;
        dp = nd;
    }
    return dp[s];
}
--py

### countpaths
--idea
Counting paths asks how many different routes lead from a start to an end. On a grid where you may only move right or down, the number of ways to reach a cell is the ways to reach the cell above plus the ways to reach the cell on its left, because every route arrives from one of those two. Blocked cells have zero ways.
This works because routes that arrive from different neighbours are different routes, and routes that arrive from the same neighbour just extend that neighbour's routes. Nothing is counted twice and nothing is missed.
--build
1. State: `ways[i][j]` is the number of distinct routes from `(0, 0)` to cell `(i, j)` moving only right or down.
2. Transition: if the cell is blocked, `ways[i][j] = 0`. Otherwise `ways[i][j] = ways[i-1][j] + ways[i][j-1]` (a missing neighbour counts as 0).
3. Base case: `ways[0][0] = 1` if the start is open (0 if blocked).
4. Order to fill: row by row, left to right.
5. Read the answer: `ways[n-1][m-1]`.
6. Counts grow fast, so the code keeps them modulo `M = 1,000,000,007`: the addition is the code piece `addMod`, and the row is made by the code piece `newTable(m - 1, 0)` (`m` zeros). Memory: a single row works: `row[j] += row[j-1]` after setting blocked cells to 0, because `row[j]` before the update already holds the value from above.
--think
- Signal: "how many ways", moves restricted to a direction, grid or lattice, obstacles. For an empty grid the answer is a binomial coefficient, `C(n + m - 2, n - 1)`, which is faster for large grids. With obstacles use the table.
- Counts overflow quickly, so reduce modulo a prime at each addition (the code piece `addMod` does it).
- Counting paths in any directed acyclic graph (DAG, a graph with no cycles) is the same idea in topological order: `ways[v] = sum of ways[u]` over edges `u -> v`. See DP on DAGs.
- Counting shortest paths in a general graph uses a shortest-path search that adds counts when distances tie.
- Pitfalls: not zeroing blocked cells in the rolling row version; blocked start or end; mixing up "number of paths" with "shortest path".
--cost
Time O(rows times columns). Space O(columns).
--java
static long countPaths(int[][] g) {              // g[i][j] == 1 means blocked
    final int M = 1_000_000_007;
    int n = g.length, m = g[0].length;
    long[] row = newTable(m - 1, 0);             // m zeros
    row[0] = g[0][0] == 1 ? 0 : 1;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++) {
            if (g[i][j] == 1) { row[j] = 0; continue; }      // blocked: no way in
            if (i == 0 && j == 0) continue;
            if (j > 0) row[j] = addMod((int) row[j], (int) row[j - 1], M);  // left + above
        }
    return row[m - 1];
}
--py

### dpstrings
--idea
DP on strings uses a table indexed by prefixes (the first `i` characters), so the answer for a long string is built from answers for shorter prefixes. A prefix is the string cut off at some point. The example is word break: in how many ways can a string be cut into pieces so that every piece is a word from a given dictionary? (A result of 0 means it cannot be split.)
The ways for the prefix of length `i` are the sum, over every cut point `j` before it where the piece between `j` and `i` is a word, of the ways for the prefix of length `j`.
--build
1. State: `ways[i]` is the number of ways to split the first `i` characters of `s` entirely into dictionary words. The table comes from the code piece `newTable(n, 0)`.
2. Transition: `ways[i] = sum of ways[j]` over every `j < i` where `s[j..i)` (characters from index `j` up to but not including `i`) is in the dictionary.
3. Base case: `ways[0] = 1`, the empty prefix has exactly one split (no words).
4. Order to fill: `i` from 1 to `n`, each looking at smaller `j`.
5. Read the answer: `ways[n]`. It is 0 when the string cannot be split, and positive when it can.
6. Speed: put the words in a hash set, and only try `j` where `i - j` is at most the longest word length.
--think
- Signal: "split a string into pieces from a set", "number of ways to decode", "can the string be formed". The state is a prefix length, and the transition looks at the last piece.
- For a plain yes or no, replace the sum with `or` on booleans. Counting is the same table with `+`, and covers decode ways and sentence breaks. Real counts can be huge, so many problems ask for them modulo a prime.
- Decide the last piece, not the first. It keeps the table one-dimensional.
- Neighbours: two-sequence DP when there are two strings; KMP or a trie speeds up the word check when the dictionary is large; edit distance for fuzzy matching.
- Pitfalls: slicing cost (Python slices copy, so cap the piece length); the empty prefix base; a dictionary with an empty word (skip it or the loop stalls).
--cost
Time O(n times L) hash checks where `L` is the longest word, each comparing up to `L` characters. Space O(n plus dictionary).
--java
static long countBreaks(String s, List<String> words) {
    Set<String> dict = new HashSet<>(words);
    int n = s.length(), maxLen = 0;
    for (String w : words) maxLen = Math.max(maxLen, w.length());
    long[] ways = newTable(n, 0);
    ways[0] = 1;                                 // empty prefix: one split
    for (int i = 1; i <= n; i++)
        for (int j = Math.max(0, i - maxLen); j < i; j++)
            if (dict.contains(s.substring(j, i))) ways[i] += ways[j];
    return ways[n];
}
--py
def count_breaks(s, words):
    dict_ = set(words)

    max_len = max((len(w) for w in words), default=0)
    ways = new_table(n, 0)
    ways[0] = 1                                  # empty prefix: one split
    for i in range(1, n + 1):
        for j in range(max(0, i - max_len), i):

--cpp

### lis
--idea
The longest increasing subsequence (LIS) is the longest list of numbers you can pick from a sequence, keeping their order, so that each is bigger than the one before. In 10, 9, 2, 5, 3, 7, 101, 18 one answer is 2, 3, 7, 18 with length 4. They do not have to be next to each other.
For each position, ask: what is the longest increasing subsequence that ends exactly here? It is one more than the best such value among earlier, smaller numbers, or just 1 if there are none.
--build
1. State: `len[i]` is the length of the longest strictly increasing subsequence that ends with the element at index `i`.
2. Transition: `len[i] = 1 + max(len[j])` over all `j < i` with `a[j] < a[i]`. If there is no such `j`, `len[i] = 1`.
3. Base case: every element alone is a subsequence of length 1, so start `len[i] = 1`.
4. The max in step 2 is the code piece `chmax`. Order to fill: `i` from 0 to `n - 1`.
5. Read the answer: the maximum of all `len[i]`, since the sequence may end anywhere.
6. To print it, store `prev[i]`, the `j` that gave the max, and follow it back from the best `i`.
--think
- Signal: "longest", "subsequence", "increasing" (or non-decreasing, or any chain in an order). Also hidden forms: nesting envelopes or boxes (sort by one dimension, then LIS on the other), longest chain of pairs, minimum number of piles.
- Strict versus non-strict: strictly increasing uses `a[j] < a[i]`. Non-decreasing uses `a[j] <= a[i]`. Check the statement.
- This version is O(n squared), fine up to a few thousand. For more, use LIS in n log n.
- Neighbour: LIS equals the LCS of the sequence and its sorted copy (when values are distinct). Counting the number of LIS needs a second array of counts.
- Pitfalls: returning `len[n-1]` instead of the max; confusing subsequence (gaps allowed) with subarray (contiguous); empty input.
--cost
Time O(n squared). Space O(n).
--java
static int lis(int[] a) {
    int n = a.length;
    long[] len = new long[n], best = {0};
    for (int i = 0; i < n; i++) {
        len[i] = 1;                              // the element alone
        for (int j = 0; j < i; j++)
            if (a[j] < a[i]) chmax(len, i, len[j] + 1);
        chmax(best, 0, len[i]);                  // may end anywhere
    }
    return (int) best[0];
}
--py

### lisfast
--idea
LIS in n log n keeps a short list called `tails`. For each length `L`, `tails[L-1]` stores the smallest possible last value of an increasing subsequence of length `L`. A smaller last value is always better, because it is easier to extend.
Handle the numbers one by one. For a new number `x`, find the first spot in `tails` that is not smaller than `x` and put `x` there. If every entry is smaller than `x`, append it, which grows the longest length by one. The list `tails` stays sorted, so the spot is found by binary search.
--build
1. Keep the array `tails` with one slot per input element, all filled with a huge value `BIG` that means "slot not used yet". The used slots always form a prefix and are strictly increasing.
2. For each number `x` in order, find `pos = lowerBound(tails, x)`, the first index with `tails[pos] >= x`. This is the code piece `lowerBound` (binary search).
3. Set `tails[pos] = x`. If `pos` was an unused slot this makes the longest length one bigger; otherwise `x` is a better (smaller) end for length `pos + 1`.
4. State meaning: `tails[k]` is the smallest possible last element over all increasing subsequences of length `k + 1` seen so far (or `BIG` if none exists).
5. Base case: all slots `BIG`. Order: left to right over the input.
6. Read the answer: the number of used slots, which is `lowerBound(tails, BIG)`, the first unused slot. Note: `tails` itself is not the actual subsequence, only its length is correct. To rebuild, also store for each element its slot and a parent pointer. Inputs must be smaller than `BIG`.
--think
- Signal: LIS with n up to 100 thousand or more.
- Invariant: `tails` is strictly increasing, and each entry is the best possible end for its length. Replacing at `pos` keeps both true because `x` is not larger than the old entry yet still bigger than the entry before it.
- Strict versus non-decreasing is chosen by the binary search: lower bound (first `>= x`) for strictly increasing, upper bound (first `> x`) for non-decreasing. Getting this wrong is the most common bug.
- Relation to the O(n squared) version: the first stores the best length per ending element, this one stores the best ending element per length, and swapping the roles lets binary search work.
- Neighbours: patience sorting (same idea with piles of cards), nesting boxes and envelopes (sort widths ascending, heights descending for ties, then LIS on heights), segment tree LIS when you also need weights.
- Pitfalls: believing `tails` is the answer sequence; wrong bound function; sorting ties the wrong way in the envelope trick.
--cost
Time O(n log n). Space O(n).
--java
static int lisFast(int[] a) {
    int[] tails = new int[a.length];
    Arrays.fill(tails, Integer.MAX_VALUE);       // MAX_VALUE = slot not used yet
    for (int x : a)
        tails[lowerBound(tails, x)] = x;         // first slot with tails[pos] >= x
    return lowerBound(tails, Integer.MAX_VALUE); // number of used slots
}

### boundedk
--idea
Bounded knapsack: each item type has a limited count, for example 3 copies of an item. You still want the most value in a bag of limited weight. You could repeat the item 3 times in a 0/1 knapsack, but with big counts that is slow.
Binary splitting fixes it. Any count from 0 to `c` can be built by picking some of the chunks 1, 2, 4, ..., and a leftover. A count of 13 splits into 1, 2, 4, 6. Every number from 0 to 13 is a sum of some of these chunks, and none exceeds 13. Treat each chunk as one 0/1 item that is the item repeated chunk times.
--build
1. For each item type with weight `w`, value `v` and count `c`, split `c` into chunks: `k = 1`, while `c > 0` take `t = min(k, c)`, make a new item of weight `t * w` and value `t * v`, then `c -= t`, `k *= 2`. Collect all chunk weights in `cw` and values in `cv`.
2. State: `dp[x]` is the best value for a bag of capacity `x` using the chunk items processed so far, each chunk at most once.
3. Transition: for each chunk `(W, V)` and `x` from `cap` down to `W`: `dp[x] = max(dp[x], dp[x - W] + V)`.
4. Base case: `dp[x] = 0` for all `x` (leftover room is allowed).
5. Order to fill: chunk by chunk, capacity downward (0/1 style).
6. Steps 2 to 5 are the code piece `knapsack`, so the code only builds the chunk lists and calls `knapsack(cw, cv, cap)`. Read the answer from its return value, `dp[cap]`.
--think
- Signal: item types with a stock limit, such as "at most 5 of these". Total work becomes O(cap times the sum of log of counts) instead of the sum of counts.
- Why the chunks are exact: with chunks 1, 2, 4, ..., 2^(m-1) and a final leftover, every total from 0 to `c` is reachable, and no total above `c` is. That is why the leftover is `c - (2^m - 1)` rather than the next power of two.
- Even faster for big counts and small capacity: a monotonic queue per residue class of weight gives O(cap) per type. Use it when the chunk method is too slow.
- Neighbours: 0/1 knapsack (count 1), unbounded knapsack (count infinite, or at least `cap / w`).
- Pitfalls: using the next power of two for the last chunk (allows more copies than stock); looping capacity upward; forgetting to multiply both weight and value.
--cost
Time O(cap times the sum over types of log(count)). Space O(cap).
--java
static long boundedKnapsack(int[] w, int[] v, int[] cnt, int cap) {
    List<Integer> cw = new ArrayList<>(), cv = new ArrayList<>();
    for (int i = 0; i < w.length; i++) {
        int c = cnt[i];
        for (int k = 1; c > 0; k <<= 1) {
            int t = Math.min(k, c);              // chunk of t copies
            c -= t;
            cw.add(t * w[i]);
            cv.add(t * v[i]);
        }
    }
    int[] W = cw.stream().mapToInt(Integer::intValue).toArray();
    int[] V = cv.stream().mapToInt(Integer::intValue).toArray();
    return knapsack(W, V, cap);                  // 0/1 knapsack on the chunks
}
--py
def bounded_knapsack(w, v, cnt, cap):
    cw, cv = [], []
    for i in range(len(w)):
        c, k = cnt[i], 1
        while c > 0:
            t = min(k, c)                        # chunk of t copies
            c -= t
            k *= 2
            cw.append(t * w[i])
            cv.append(t * v[i])
    return knapsack(cw, cv, cap)                 # 0/1 knapsack on the chunks
--cpp

            cw.push_back(t * w[i]);
            cv.push_back(t * v[i]);
        }
    }

}

### knapbitset
--idea
A bitset is a row of bits stored many to a machine word, so one instruction handles 64 of them at once. For subset sum, store the set of reachable totals as bits: bit `s` is 1 when the total `s` can be made. Adding a number `x` means "every reachable total, shifted up by `x`, is reachable too", which is one shift and one OR on the whole row.
So the inner loop over `s` disappears into a few word operations, making the DP about 64 times faster. It is the same DP as subset sum, only stored compactly.
--build
1. State: bit `s` of `bits` is 1 when some subset of the numbers processed so far adds up to exactly `s`. Keep only totals up to `cap`.
2. Transition: for each number `x`, `bits = bits OR (bits shifted left by x)`. The old bits stay (not taking `x`), the shifted copy is "taking `x`". Both read the old value, so each number is used once.
3. Base case: `bits = 1`, only bit 0 set (the empty subset).
4. Order to fill: numbers one at a time, any order.
5. Read the answer: bit `target` for "is it reachable". The number of 1 bits in positions 0 to `cap` is how many different totals are reachable.
6. Where the language has no bitset of dynamic size (Java), shift by hand: move whole words by `x / 64` and the remaining `x % 64` bits across the word boundary, going from the highest word down so the old values are still unread.
--think
- Signal: subset sum or 0/1 knapsack feasibility where `n times cap` is too big for a plain table, but `n times cap / 64` is fine (about 10 to the 9 to 10 to the 10 in total).
- It answers yes or no, not values. For "best value" you need the normal table, but a bitset still helps counting which sums are possible.
- Bounded counts: chunk the counts by binary splitting (as in bounded knapsack) and shift by chunk weights.
- Neighbours: subset sum, partition. In graph problems the same trick speeds up reachability tables (transitive closure) and similar boolean DPs.
- Pitfalls: bits above `cap` pollute counts (mask them or only count up to `cap`); shifting by more than the width; in C++ the bitset size is fixed at compile time, so pick a generous constant; Python integers work well as a bitset: `bits |= bits << x`.
--cost
Time O(n times cap / 64). Space O(cap / 64) words.
--java
static int reachableSums(int[] a, int cap) {
    int words = cap / 64 + 1;
    long[] bits = new long[words];
    bits[0] = 1L;                                // only the empty sum
    for (int x : a) {
        int q = x / 64, r = x % 64;
        for (int i = words - 1; i >= q; i--) {   // high to low: old values still unread
            long add = bits[i - q] << r;
            if (r > 0 && i - q - 1 >= 0) add |= bits[i - q - 1] >>> (64 - r);
            bits[i] |= add;
        }
    }
    int count = 0;
    for (int s = 0; s <= cap; s++)
        if ((bits[s >> 6] >>> (s & 63) & 1L) != 0) count++;
    return count;
}
--py
def reachable_sums(a, cap):
    mask = (1 << (cap + 1)) - 1                  # keep totals 0..cap only
    bits = 1                                     # only the empty sum
    for x in a:
        bits |= (bits << x) & mask               # take x, or not
    return bin(bits).count("1")
--cpp
int reachableSums(const vector<int>& a, int cap) {
    const int MAXC = 100001;                     // compile-time size, must exceed cap
    bitset<MAXC> bits;
    bits[0] = 1;                                 // only the empty sum
    for (int x : a) bits |= bits << x;           // take x, or not
    int count = 0;
    for (int s = 0; s <= cap; s++) count += bits[s];
    return count;
}

### multiknap
--idea
In a multi-dimensional knapsack each item uses several kinds of resource at once, for example weight and volume, and the bag has a separate limit for each. You must stay within every limit. The picture is a table with one axis per resource.
Nothing new is needed beyond knapsack: the capacity becomes a pair (or more) of numbers, so the state is a table over both limits. Each item is taken once, so both loops go downward.
--build
1. State: `dp[a][b]` is the best value using the items so far with at most `a` units of the first resource and at most `b` of the second.
2. Transition: for each item with costs `(c1, c2)` and value `v`, for `a` from `cap1` down to `c1` and `b` from `cap2` down to `c2`: `dp[a][b] = max(dp[a][b], dp[a - c1][b - c2] + v)`.
3. Base case: all zeros (leftover room is allowed). Each row is made with the code piece `newTable(cap2, 0)`.
4. Order to fill: items one by one; both capacity loops go downward so each item is used once.
5. Read the answer: `dp[cap1][cap2]`.
--think
- Signal: "at most x of this and at most y of that", two budgets (money and time), a bag with weight and count limits, "use at most k items" (the count is a second resource with cost 1 each).
- The table size is the product of the limits, so it works only for small limits. For three or more limits it grows fast; at that point look for structure, or search heuristics.
- Neighbours: 0/1 knapsack (one limit), bounded knapsack (stock limits on items), "at most k items" is the special case where the second resource costs 1 per item.
- Pitfalls: looping one dimension upward by mistake; mixing the two costs in the index; order of nested loops does not matter as long as both go downward.
--cost
Time O(items times cap1 times cap2). Space O(cap1 times cap2).
--java
static int multiKnapsack(int[] c1, int[] c2, int[] v, int cap1, int cap2) {
    long[][] dp = new long[cap1 + 1][];
    for (int a = 0; a <= cap1; a++) dp[a] = newTable(cap2, 0);   // all zeros
    for (int i = 0; i < v.length; i++)
        for (int a = cap1; a >= c1[i]; a--)          // both downward: item once
            for (int b = cap2; b >= c2[i]; b--)
                dp[a][b] = Math.max(dp[a][b], dp[a - c1[i]][b - c2[i]] + v[i]);
    return (int) dp[cap1][cap2];
}
--py
def multi_knapsack(c1, c2, v, cap1, cap2):
    dp = [new_table(cap2, 0) for _ in range(cap1 + 1)]   # all zeros
    for i in range(len(v)):
        for a in range(cap1, c1[i] - 1, -1):         # both downward: item once
            for b in range(cap2, c2[i] - 1, -1):
                dp[a][b] = max(dp[a][b], dp[a - c1[i]][b - c2[i]] + v[i])
    return dp[cap1][cap2]
--cpp

### interval
--idea
Interval DP stores an answer for every range (interval) `[i, j]` of a sequence, and builds the answer for a long range from the answers of shorter ranges inside it. The picture: a long rope that you cut into two shorter ropes at some point, solve each piece, and join the results.
The example is merging piles. You have piles of stones in a row. Merging two neighbouring piles costs their combined size. Find the cheapest way to merge everything into one pile. The last merge joins a left block and a right block, and those blocks were merged independently before. So try every cut point for the last merge.
--build
1. State: `dp[i][j]` is the least cost to merge piles `i` through `j` (both included) into one pile.
2. Transition: `dp[i][j] = min over k from i to j-1 of (dp[i][k] + dp[k+1][j]) + sum(i..j)`. The cut `k` splits the range into a left block and a right block; the final merge costs the total of the whole range, found from a prefix sum `pre`: `sum(i..j) = pre[j+1] - pre[i]`.
3. The table rows come from the code piece `newTable(n - 1, 0)` (`n` zeros). Base case: `dp[i][i] = 0`, a single pile needs no merge.
4. Order to fill: by range length, from 2 up to `n`. For each length, every start `i` with `j = i + length - 1`. All shorter ranges are done before a longer one.
5. Read the answer: `dp[0][n-1]`, the whole row.
--think
- Signal: a line of items, you repeatedly combine or remove neighbours, the cost depends on the range, and the result is a tree of choices (parenthesisation). Also "cut a stick", "burst balloons", "optimal polygon triangulation".
- Choose the state as the range. Then ask: what is the last (or first) thing that happens inside the range? That choice splits the range into independent smaller ones. Choosing the last operation is usually the right way, because the pieces then do not interact.
- Neighbours: matrix chain multiplication and burst balloons are the same shape with different split costs; palindromic DPs are interval DPs with an O(1) transition; Knuth optimisation speeds up the cubic form to quadratic when its conditions hold.
- Pitfalls: looping `i` and `j` in the wrong order so a shorter range is not ready (always loop by length); forgetting the prefix sums; allowing `k = j`, which makes an empty right block; overflow of the sums.
--cost
Time O(n cubed): O(n squared) ranges, O(n) cuts each. Space O(n squared).
--java
static long mergeCost(int[] a) {
    int n = a.length;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    long[][] dp = new long[n][];
    for (int i = 0; i < n; i++) dp[i] = newTable(n - 1, 0);   // single piles cost 0
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            long best = Long.MAX_VALUE;
            for (int k = i; k < j; k++)          // last merge joins [i..k] and [k+1..j]
                best = Math.min(best, dp[i][k] + dp[k + 1][j]);
            dp[i][j] = best + pre[j + 1] - pre[i];
        }
    return dp[0][n - 1];
}
--py

### matrixchain
--idea
Multiplying a chain of matrices gives the same result whichever way you put the brackets, but the number of scalar multiplications (single number times number) changes a lot. A matrix with `p` rows and `q` columns times one with `q` rows and `r` columns costs `p * q * r`. For three matrices, (A B) C and A (B C) can differ by a factor of ten or more. The task is to pick the bracketing with the fewest multiplications.
The last multiplication splits the chain into a left part and a right part, each already multiplied into one matrix. So try every split point and add the costs of the two parts plus the cost of joining their results.
--build
1. Input: `p` of length `n + 1`. Matrix `i` (0-based) has `p[i]` rows and `p[i+1]` columns, so neighbours always fit.
2. State: `dp[i][j]` is the fewest scalar multiplications to multiply matrices `i` through `j` into one matrix.
3. Transition: `dp[i][j] = min over k from i to j-1 of dp[i][k] + dp[k+1][j] + p[i] * p[k+1] * p[j+1]`. The left product is `p[i]` by `p[k+1]`, the right is `p[k+1]` by `p[j+1]`, and joining them costs that triple product.
4. The table rows come from the code piece `newTable(n - 1, 0)` (`n` zeros). Base case: `dp[i][i] = 0`, one matrix needs no work.
5. Order to fill: by chain length from 2 to `n`, since longer chains need shorter ones.
6. Read the answer: `dp[0][n-1]`. To print the bracketing, also store the best `k` for each range and rebuild recursively.
--think
- Signal: "order of operations changes the cost" while the result is the same, an associative operation on a sequence. The state is a contiguous range of the chain.
- The question to ask is "which operation is the last one". The last split gives two independent subchains, which is why the cut-point recursion is complete.
- Same family: optimal merge of piles, polygon triangulation (the same recurrence with a different join cost), optimal binary search tree. Hu-Shing gives O(n log n) for this exact problem, but the cubic DP is the standard answer.
- Pitfalls: mixing up the dimension indexes (`p[k+1]` is the shared dimension at the cut); using `int` for the product of three dimensions (use `long`); a chain of one matrix.
--cost
Time O(n cubed). Space O(n squared).
--java
static long matrixChain(int[] p) {
    int n = p.length - 1;                        // number of matrices
    long[][] dp = new long[n][];
    for (int i = 0; i < n; i++) dp[i] = newTable(n - 1, 0);   // one matrix costs 0
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            long best = Long.MAX_VALUE;
            for (int k = i; k < j; k++)          // last multiplication splits at k
                best = Math.min(best, dp[i][k] + dp[k + 1][j] + (long) p[i] * p[k + 1] * p[j + 1]);
            dp[i][j] = best;
        }
    return dp[0][n - 1];
}

### burst
--idea
Burst balloons: balloons in a row have numbers. Bursting balloon `k` earns `left * k * right` coins, where `left` and `right` are its current neighbours (a missing neighbour counts as 1). Find the order of bursts that earns the most.
The trick is to think about the last balloon to burst in a range, not the first. When balloon `k` is the last one left in a range, its neighbours are the walls of the range, which do not change. Everything inside to the left and right of `k` has already burst, and those two sides do not interact. That makes the two sides independent subproblems. Thinking about the first burst fails because it changes the neighbours of the rest.
--build
1. Pad the array: `a = [1] + nums + [1]`. Positions 0 and `n + 1` are walls that are never burst.
2. State: `dp[l][r]` is the most coins from bursting every balloon strictly between positions `l` and `r` (walls `l` and `r` stay).
3. Transition: `dp[l][r] = max over k from l+1 to r-1 of dp[l][k] + dp[k][r] + a[l] * a[k] * a[r]`. Here `k` is the last balloon burst in the open range.
4. The table rows come from the code piece `newTable(n + 1, 0)` (`n + 2` zeros). Base case: when `r - l < 2` there is no balloon between, so `dp[l][r] = 0`.
5. Order to fill: by gap `r - l` from 2 up to `n + 1`.
6. Read the answer: `dp[0][n+1]`.
--think
- Signal: removing items one at a time where each removal's reward depends on its current neighbours. The neighbours change, so state the problem on a range with fixed walls and choose the last item.
- General rule: if "first" makes the pieces depend on each other, flip to "last". The same flip solves "cutting a stick" and "removing boxes".
- The range is open (walls excluded), which is why `k` runs strictly between `l` and `r`.
- Neighbours: matrix chain multiplication (identical shape), interval DP in general, and Knuth optimisation when conditions allow.
- Pitfalls: choosing the first burst (wrong); forgetting the padding of 1s; zero balloons; using the inclusive range convention for the walls.
--cost
Time O(n cubed). Space O(n squared).
--java
static int burst(int[] nums) {
    int n = nums.length;
    int[] a = new int[n + 2];
    a[0] = a[n + 1] = 1;                         // walls
    for (int i = 0; i < n; i++) a[i + 1] = nums[i];
    long[][] dp = new long[n + 2][];
    for (int i = 0; i < n + 2; i++) dp[i] = newTable(n + 1, 0);   // empty ranges stay 0
    for (int gap = 2; gap <= n + 1; gap++)
        for (int l = 0; l + gap <= n + 1; l++) {
            int r = l + gap;
            for (int k = l + 1; k < r; k++)      // k is the LAST balloon burst
                dp[l][r] = Math.max(dp[l][r], dp[l][k] + dp[k][r] + a[l] * a[k] * a[r]);
        }
    return (int) dp[0][n + 1];
}

### bitmask
--idea
A bitmask is one integer whose binary digits say which items of a small set are chosen: bit `i` is 1 when item `i` is in. With `n` items there are 2 to the power `n` masks, so this works for `n` up to about 20. Bitmask DP uses the mask as the state, so the DP can remember exactly which items are already used.
The example is the elevator problem: `n` people with weights must all ride an elevator that carries at most `W` per trip. Find the fewest trips. The order people board matters, and subsets are the right memory. For each set of people already carried, record the best way to have carried them: fewest trips, and among those the smallest weight on the last trip.
--build
Small steps:
1. Number the people 0 to `n - 1`. A mask is a subset: `mask >> i & 1` tests person `i`, `mask | (1 << i)` adds person `i`.
2. State: `dp[mask]` is a pair `(trips, load)`: the fewest trips to carry exactly the people in `mask`, and, among plans with that many trips, the smallest load on the last (current) trip. Compare pairs lexicographically (trips first, then load).
3. Why the pair works: fewer trips always wins, because starting a new trip is possible later; with equal trips, a smaller last load leaves more room. So the best pair is the only one worth keeping (this must hold for the state to be valid).
4. Base case: `dp[0] = (1, 0)`: with nobody carried we have one trip open with load 0.
5. Transition: for each `mask` and each person `i` not in it (the code lists them with the code piece `itemsIn(full ^ mask, n)`, the items of the complement), let `(t, l) = dp[mask]`. If `l + w[i] <= W`, the candidate for `mask | (1 << i)` is `(t, l + w[i])`. Otherwise it is `(t + 1, w[i])`. Keep the smaller candidate.
6. Order to fill: masks from 0 up to `2^n - 1`. Adding a bit makes the number bigger, so every predecessor is done first.
7. Read the answer: `dp[(1 << n) - 1].trips`. Assume each weight is at most `W`.
--think
- Signal: `n` at most about 20, "assign", "visit all", "partition into groups", "each item used once, order matters in cost". The small `n` is the clue.
- State choice: the mask says which items are used. Add the smallest extra detail the transition needs (here the load of the open trip; for a tour, the last city).
- Check the validity of the compact state before relying on it: two partial plans for the same mask are comparable only if one is never worse in the future. That is the "must hold" condition.
- Neighbours: travelling salesman and assignment are bitmask DPs with a last-visited index or a worker count; subset enumeration ("submask") DP is the 3 to the `n` version; SOS DP speeds up sums over subsets.
- Pitfalls: `1 << i` overflowing `int` when `i >= 31` (use `1L` or a smaller `n`); iterating masks in the wrong direction; forgetting the memory of 2 to the `n` times state size (20 items with 20 extra values is 20 million entries).
--cost
Time O(2^n times n). Space O(2^n).
--java
static int elevatorTrips(int[] w, int W) {
    int n = w.length, full = (1 << n) - 1;
    int[] trips = new int[full + 1], load = new int[full + 1];
    Arrays.fill(trips, Integer.MAX_VALUE);
    trips[0] = 1; load[0] = 0;                   // one open trip, empty
    for (int mask = 0; mask < full; mask++) {
        if (trips[mask] == Integer.MAX_VALUE) continue;
        for (int i : itemsIn(full ^ mask, n)) {  // people not carried yet
            int nt = trips[mask], nl = load[mask] + w[i];
            if (nl > W) { nt++; nl = w[i]; }     // start a new trip
            int nm = mask | (1 << i);
            if (nt < trips[nm] || (nt == trips[nm] && nl < load[nm])) {
                trips[nm] = nt; load[nm] = nl;
            }
        }
    }
    return trips[full];
}

        }

### tspdp
--idea
The travelling salesman problem (TSP): visit every city exactly once, return to the start, and keep the total distance as small as possible. Trying all orders takes `n!` steps. The Held-Karp DP does it in about `n squared times 2^n`, fine for `n` up to about 20.
The insight: to extend a partial tour, you only need to know which cities were visited and which one you are standing on. The order of the earlier visits does not affect the future. So the memory is a subset of visited cities plus the current city.
--build
1. Fix city 0 as the start. Number cities 0 to `n - 1`. A mask is the set of visited cities; city 0 is always in it.
2. State: `dp[mask][j]` is the shortest length of a path that starts at city 0, visits exactly the cities in `mask`, and ends at city `j` (where `j` is in `mask`).
3. Transition (the code walks the sets with the code piece `itemsIn`, and adds distances with `safeAdd` so INF stays INF): for each unvisited city `k`, `dp[mask | (1 << k)][k] = min(dp[mask][j] + d[j][k])` over all `j` in `mask`. In words, "go from `j` to `k` next".
4. Base case: `dp[1][0] = 0` (only city 0 visited, standing at 0). All other entries are infinity.
5. Order to fill: masks from small to large numerically; adding a bit only increases the number, so all predecessors are ready.
6. Read the answer: the tour must come home, so the answer is `min over j of dp[full][j] + d[j][0]`, where `full` has all `n` bits set.
--think
- Signal: "visit every node once" on at most about 20 nodes, shortest or cheapest tour or path (a path variant has no return edge and no fixed start: initialise `dp[1 << j][j] = 0` for all `j` and drop the closing edge).
- Why the start is fixed: a tour is a cycle, so any city can be the start. Fixing it removes a factor of `n`.
- Weighted distances may violate the triangle inequality; the DP does not care. It requires every city visited once, so if shortcuts through visited cities are allowed, first run all-pairs shortest paths (Floyd-Warshall) and use those as `d`.
- Memory is 2^n times n entries; for n = 20 that is about 20 million numbers. Use `int` if the distances allow.
- Neighbours: bitmask DP (general), assignment DP (a `mask` without a last city), and for much larger `n` only heuristics exist (the problem is NP-hard).
- Pitfalls: not starting from a fixed city; forgetting the return edge; infinity added to a distance and overflowing; missing unreachable cities (use infinity for missing edges).
--cost
Time O(2^n times n squared). Space O(2^n times n).
--java
static int tsp(int[][] d) {
    int n = d.length, full = (1 << n) - 1;
    int[][] dp = new int[full + 1][n];
    for (int[] row : dp) Arrays.fill(row, INF);  // INF from the code piece u-inf
    dp[1][0] = 0;                                // start at city 0
    for (int mask = 1; mask <= full; mask += 2)  // only masks containing city 0
        for (int j : itemsIn(mask, n)) {         // standing at j
            if (dp[mask][j] >= INF) continue;
            for (int k : itemsIn(full ^ mask, n)) {          // go on to unvisited k
                int nm = mask | (1 << k);
                dp[nm][k] = Math.min(dp[nm][k], safeAdd(dp[mask][j], d[j][k]));
            }
        }
    int ans = INF;
    for (int j = 0; j < n; j++)
        ans = Math.min(ans, safeAdd(dp[full][j], d[j][0]));  // come home
    return ans;
}

### assigndp
--idea
The assignment problem: `n` workers and `n` jobs, and `cost[i][j]` is what it costs for worker `i` to do job `j`. Give each worker one job, each job to one worker, and minimise the total. Trying all matchings is `n!`.
Bitmask DP handles `n` up to about 20 with one nice trick: process workers in order. If the set of jobs already taken is `mask`, then exactly `popcount(mask)` workers have been placed (popcount is the number of 1 bits), so the next worker is worker number `popcount(mask)`. The mask alone tells you whose turn it is, and no extra index is needed.
--build
1. State: `dp[mask]` is the least total cost to give jobs in `mask` to the first `popcount(mask)` workers, one job each.
2. Transition: let `i = popcount(mask)` (the code uses the length of the code piece `itemsIn(mask, n)`). For every job `j` not in `mask` (the code lists them with `itemsIn(full ^ mask, n)`), `dp[mask | (1 << j)] = min(dp[mask] + cost[i][j])`. In words, worker `i` takes job `j`.
3. Base case: `dp[0] = 0`. All other entries start at infinity.
4. Order to fill: masks from 0 up to `2^n - 1`. Setting a bit raises the number, so all predecessors are ready.
5. Read the answer: `dp[(1 << n) - 1]`.
--think
- Signal: one-to-one matching with costs, `n` up to about 20, or "assign each person a task". Variants: some jobs may remain (`n` workers, `m` jobs with `m` larger: the same DP with the answer being the best mask having `n` bits) and compatibility constraints (skip forbidden pairs).
- For `n` in the hundreds, use the Hungarian algorithm (O(n cubed)) or min-cost flow instead. The bitmask version is the choice when the cost depends on the set, not only on pairs.
- Why the single mask is enough: the worker order is fixed, so the only open choice is the set of jobs used.
- Neighbours: travelling salesman DP (mask plus last city), bitmask DP, and sorting-based greedy when costs have special structure.
- Pitfalls: building the DP over workers and jobs both (square memory); infinity overflow; counting bits slowly (use `Integer.bitCount`, `__builtin_popcount`, or `bin(x).count('1')`).
--cost
Time O(2^n times n). Space O(2^n).
--java
static long assignment(int[][] cost) {
    int n = cost.length, full = (1 << n) - 1;
    long INF = Long.MAX_VALUE / 4;
    long[] dp = new long[full + 1];
    Arrays.fill(dp, INF);
    dp[0] = 0;
    for (int mask = 0; mask < full; mask++) {
        if (dp[mask] >= INF) continue;
        int i = itemsIn(mask, n).size();         // next worker to place
        for (int j : itemsIn(full ^ mask, n)) {  // jobs still free
            int nm = mask | (1 << j);
            dp[nm] = Math.min(dp[nm], dp[mask] + cost[i][j]);
        }
    }
    return dp[full];
}

### treedp
--idea
Tree DP computes, for every node, an answer about the subtree below it (the node and everything beneath it), using the answers of its children. A tree has no cycles, so the subtrees of different children never overlap, and combining them is simple.
The example is the heaviest set of nodes where no two chosen nodes are directly connected (a maximum weight independent set). For each node we keep two numbers: the best total in its subtree if the node is chosen, and the best if it is not. A chosen node forces its children to be skipped; a skipped node lets each child be either.
--build
1. Root the tree at node 0. Every other node gets a parent. Compute an order where parents come before children (a breadth-first order), and then process nodes in reverse so children come before parents. This also avoids deep recursion.
2. State: `take[u]` is the best total weight inside the subtree of `u` when `u` is chosen. `skip[u]` is the best total when `u` is not chosen.
3. Transition: `take[u] = w[u] + sum of skip[c]` over children `c`. `skip[u] = sum of max(take[c], skip[c])` over children `c`.
4. Base case: a leaf has `take = w[u]` and `skip = 0`. Start every `take[u]` at `w[u]` and `skip[u]` at 0, then add each child's contribution into its parent.
5. Order to fill: reverse breadth-first order, so a node is finished before it is added to its parent.
6. Read the answer: `max(take[root], skip[root])`.
--think
- Signal: a tree (or forest) and a choice per node whose rules involve neighbours: independent set, vertex cover, colouring, "choose k nodes", subtree sums, diameter, counting.
- State: "answer for the subtree of `u`", plus a small extra flag for what `u` itself does. If the question needs a count of chosen nodes, add a dimension (a knapsack merge over the children, O(n squared) overall when merged by sizes).
- Recursion is simplest to write but can overflow the call stack on a path of 100 thousand nodes. The reverse-order loop is safe.
- If you need the answer for every possible root, do not repeat the DP `n` times; use rerooting.
- Neighbours: DP on DAGs (a tree is a special DAG), rerooting, and heavy-light decomposition for path queries.
- Pitfalls: forgetting to exclude the parent when walking the adjacency list; summing children into the wrong parent; undirected edges added in one direction only.
--cost
Time O(n). Space O(n).
--java
static long maxIndependent(int n, int[][] edges, long[] w) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); }
    int[] parent = new int[n], order = new int[n];
    parent[0] = -1;
    int head = 0, tail = 0;
    order[tail++] = 0;
    while (head < tail) {                        // breadth-first: parents before children
        int u = order[head++];
        for (int v : adj.get(u))
            if (v != parent[u]) { parent[v] = u; order[tail++] = v; }
    }
    long[] take = w.clone(), skip = new long[n];
    for (int i = n - 1; i >= 0; i--) {           // children before parents
        int u = order[i], p = parent[u];
        if (p >= 0) {
            take[p] += skip[u];                  // parent chosen: child skipped
            skip[p] += Math.max(take[u], skip[u]);
        }
    }
    return Math.max(take[0], skip[0]);
}

### dagdp
--idea
A DAG (directed acyclic graph) is a graph with one-way edges and no cycles. Because there are no cycles, you can list the nodes in a topological order: every edge goes from an earlier node to a later one. If you process nodes in that order, by the time you reach a node, everything that can lead to it is already finished. That makes any "best over incoming edges" DP work directly.
The example: the shortest distance from node 0 to every node, where edge weights may even be negative. Dijkstra cannot handle negative weights, but on a DAG the DP needs no priority queue.
--build
1. Compute a topological order by calling the code piece `topoOrder(adj)`. Inside it is Kahn's method: count incoming edges, queue all nodes with none, repeatedly pop a node, reduce the counts of its targets and queue those that reach 0. Keep `wadj`, the same adjacency with weights, for the relaxing.
2. State: `dist[v]` is the length of the shortest path from node 0 to `v`, or infinity if `v` cannot be reached.
3. Transition: when node `u` comes up in the order (so `dist[u]` is final), relax every edge `u -> v` with weight `w`: `dist[v] = min(dist[v], dist[u] + w)`.
4. Base case: `dist[0] = 0`, all other nodes infinity. Skip nodes whose `dist` is still infinity (unreachable).
5. Order to fill: the topological order. Every edge into `v` is relaxed before `v` is popped.
6. Read the answer: `dist[t]` for the target, or the whole `dist` array.
--think
- Signal: a graph without cycles, or a problem that is really one (time-ordered events, tasks with prerequisites, "can only move forward"). If a DP's transitions always go from "smaller" states to "bigger" ones, it is already a DAG DP and the loop order is the topological order.
- The same skeleton counts paths (replace `min` and `+` with `+=`), finds longest paths (use `max`), or counts paths with a property.
- If the graph might have a cycle, Kahn's method processes fewer than `n` nodes. Check that to detect cycles.
- Neighbours: longest path in a DAG, counting paths, Dijkstra (for graphs with cycles but non-negative weights), Bellman-Ford (negative weights and cycles allowed, slower).
- Pitfalls: using `Integer.MAX_VALUE` as infinity and adding a weight to it; relaxing from an unreachable node; starting the order from a node other than the source (that is fine, since unreachable nodes are skipped).
--cost
Time O(V + E). Space O(V + E).
--java
static long[] dagShortest(int n, int[][] edges) {       // edge = {u, v, w}
    long INF2 = Long.MAX_VALUE / 4;
    List<List<Integer>> adj = new ArrayList<>();
    List<List<int[]>> wadj = new ArrayList<>();
    for (int i = 0; i < n; i++) { adj.add(new ArrayList<>()); wadj.add(new ArrayList<>()); }
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); wadj.get(e[0]).add(new int[]{e[1], e[2]}); }
    long[] dist = new long[n];
    Arrays.fill(dist, INF2);
    dist[0] = 0;
    for (int u : topoOrder(adj)) {               // code piece: topological order
        if (dist[u] >= INF2) continue;           // unreachable from node 0
        for (int[] e : wadj.get(u))
            dist[e[0]] = Math.min(dist[e[0]], dist[u] + e[1]);
    }
    return dist;
}

### longestdag
--idea
The longest path in a DAG (a directed graph with no cycles) is the heaviest chain of edges you can follow, such as the longest chain of dependent tasks, which is the minimum time to finish a project if tasks run in parallel (the critical path). On general graphs the longest path is very hard, because cycles let you loop. In a DAG there are no loops, so it is easy.
Process nodes in a topological order (every edge goes from an earlier node to a later one). The best path ending at a node is the best of the paths ending at its predecessors plus the edge, or just the node alone if that is better.
--build
1. Build the adjacency lists (plain `adj` for the order, weighted `wadj` for the relaxing). Get the topological order by calling the code piece `topoOrder(adj)`, which runs Kahn's method (a queue of nodes with no incoming edges).
2. State: `best[v]` is the largest total weight of any path that ends at `v` (it may start anywhere, and a path of just `v` has weight 0).
3. Transition: when node `u` comes up in the order, for each edge `u -> v` with weight `w`: `best[v] = max(best[v], best[u] + w)`.
4. Base case: `best[v] = 0` for all `v` (a path of a single node).
5. Order to fill: the topological order, so `best[u]` is final when `u` is processed.
6. Read the answer: the maximum of `best[v]` over all `v`. To print the path, store `parent[v]`, the `u` that gave the max, and walk back.
--think
- Signal: "longest chain", "most tasks in a sequence", "critical path", "maximum score moving only forward". Also hides inside problems like the longest increasing subsequence (nodes are items, an edge exists when one can follow the other) and nesting boxes.
- Counting edges instead of weights: give every edge weight 1.
- It is the mirror of shortest path in a DAG: swap `min` for `max`. Negative weights are fine too.
- If the graph can contain a cycle the answer may be unbounded; Kahn's method would process fewer than `n` nodes, which is how you detect it.
- Neighbours: DP on DAGs (the general idea), longest increasing subsequence, topological sort.
- Pitfalls: initialising `best` to minus infinity when paths may start anywhere (then isolated starts are lost); forgetting that the answer is the max over all nodes, not the last one.
--cost
Time O(V + E). Space O(V + E).
--java
static long longestPath(int n, int[][] edges) {         // edge = {u, v, w}
    List<List<Integer>> adj = new ArrayList<>();
    List<List<int[]>> wadj = new ArrayList<>();
    for (int i = 0; i < n; i++) { adj.add(new ArrayList<>()); wadj.add(new ArrayList<>()); }
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); wadj.get(e[0]).add(new int[]{e[1], e[2]}); }
    long[] best = new long[n];                   // path of one node weighs 0
    long ans = 0;
    for (int u : topoOrder(adj)) {               // code piece: topological order
        ans = Math.max(ans, best[u]);
        for (int[] e : wadj.get(u))
            best[e[0]] = Math.max(best[e[0]], best[u] + e[1]);
    }
    return ans;
}
--py
def longest_path(n, edges):                      # edge = (u, v, w)
    adj = [[] for _ in range(n)]
    wadj = [[] for _ in range(n)]
    for u, v, w in edges:
        adj[u].append(v)
        wadj[u].append((v, w))
    best = [0] * n                               # path of one node weighs 0
    ans = 0
    for u in topo_order(adj):                    # code piece: topological order
        ans = max(ans, best[u])
        for v, w in wadj[u]:
            best[v] = max(best[v], best[u] + w)
    return ans

}

### probdp
--idea
Probability DP tracks, for every state, the chance of being in that state at a given moment. You start with probability 1 in the starting state, and each step spreads that probability to the next states, multiplying by the chance of each move. At the end you add up the probabilities of the states you care about.
The example: toss a coin `n` times, where heads has probability `p`. What is the probability of exactly `h` heads? State after `i` tosses: the number of heads so far. A toss moves `j` heads to `j + 1` with probability `p`, or leaves it at `j` with probability `1 - p`.
--build
1. State: `dp[i][j]` is the probability that after `i` tosses there are exactly `j` heads.
2. Transition (pull form): `dp[i][j] = dp[i-1][j] * (1 - p) + dp[i-1][j-1] * p`. The last toss was tails from `j` heads, or heads from `j - 1` heads.
3. Base case: `dp[0][0] = 1`, all other entries of row 0 are 0 (before any toss we have 0 heads for sure).
4. Order to fill: `i` from 1 to `n`; each row needs only the previous row, so keep one row and update `j` downward.
5. Read the answer: `dp[n][h]`. For "at least `h`" add the entries from `h` to `n`.
--think
- Signal: "probability that", random moves, dice, cards, a random walk with limited steps. The states must be few and each state's probability must depend only on the state, not on the path.
- The probabilities of all states at a given step add up to 1. Use that to check your code.
- Pull or push: either compute a state from the states before it (pull), or send a state's probability forward (push). Both give the same table.
- Neighbours: expected value DP (asks for the average instead of a chance, and usually runs backwards), counting DP (same table with counts instead of probabilities), and matrix exponentiation for many steps.
- Floating-point: use `double`, avoid subtracting nearly equal numbers, and if the problem wants a fraction modulo a prime, multiply by modular inverses instead (for example the inverse of 6 for a fair die).
- Pitfalls: treating different orders of the same outcome as one (here the DP handles this correctly because each state is a count); forgetting the tails branch; an update order that overwrites a value before it is read.
--cost
Time O(n times h) for the table up to `h` heads, here O(n squared). Space O(n).
--java
static double probHeads(int n, int h, double p) {
    double[] dp = new double[n + 1];
    dp[0] = 1.0;                                 // before any toss: zero heads for sure
    for (int i = 1; i <= n; i++)
        for (int j = i; j >= 0; j--)             // downward: use the previous row
            dp[j] = dp[j] * (1 - p) + (j > 0 ? dp[j - 1] * p : 0);
    return dp[h];
}
--py

### expdp
--idea
Expected value DP computes the average outcome of a random process. The expected value of something is the sum of each possible result times its probability. For a state, the expected future cost equals the cost of one step plus the probability-weighted average of the expected costs of the states you can land in. That is one equation per state.
The example: you roll a fair die with `f` faces repeatedly and add the results. What is the expected number of rolls until the total reaches at least `n`? Let `E[r]` be the expected number of further rolls when `r` more points are still needed.
--build
1. State: `E[r]` is the expected number of additional rolls needed when `r` more points are required (`r` from 0 to `n`).
2. Transition: `E[r] = 1 + (1 / f) * sum of E[max(0, r - k)]` for `k` from 1 to `f`. One roll is spent, then each face `k` is equally likely and leaves `r - k` still needed (or 0 if we have overshot).
3. Base case: `E[0] = 0`, the goal is already reached. Negative remaining counts are treated as 0.
4. Order to fill: `r` from 1 up to `n`, since `E[r]` uses only smaller remaining values.
5. Read the answer: `E[n]`.
--think
- Signal: "expected number of", "average", "on average how many steps". The key is to define the state as what remains, and work backwards from the goal. That makes the equations triangular, so a single pass solves them.
- Linearity of expectation: expectations add even when events depend on each other. It often removes the need for a DP at all (the expected number of a thing equals the sum of the chances of each piece).
- When states can loop back to themselves or earlier ones (a random walk that can step backwards), the equations cannot be solved in a single pass. Move the self-term to the left: `E = 1 + p * E + rest` gives `E = (1 + rest) / (1 - p)`. For longer loops you need to solve a linear system (Gaussian elimination).
- Neighbours: probability DP (chances, not averages), game DP, and DAG DP (expected value over a DAG of states in reverse topological order).
- Pitfalls: working forwards when the base case is at the goal; dividing by zero when a state never leaves itself; adding the step cost inside the sum instead of once; in modular problems, use the modular inverse of `f`.
--cost
Time O(n times f). Space O(n).
--java
static double expectedRolls(int n, int f) {
    double[] e = new double[n + 1];              // e[0] = 0: already reached
    for (int r = 1; r <= n; r++) {
        double sum = 0;
        for (int k = 1; k <= f; k++)
            sum += e[Math.max(0, r - k)];        // overshoot leaves 0 needed
        e[r] = 1 + sum / f;                      // one roll, then the average
    }
    return e[n];
}
--py

### gamedp
--idea
Game DP solves two-player games where both play perfectly and take turns. A state is winning for the player to move if there is some move to a state that is losing for the opponent. A state is losing if every move leads to a winning state for the opponent (or there is no move at all and the rules say that player loses).
The example: a pile of `n` stones, each turn a player removes a number of stones from a given set of allowed amounts, and the player who cannot move loses. Label each pile size win or lose, working upward from the smallest.
--build
1. State: `win[s]` is true if the player to move, facing a pile of `s` stones, can force a win.
2. Transition: `win[s] = true` if some allowed removal `m <= s` has `win[s - m]` false. That is, there is a move that hands the opponent a losing position.
3. Base case: `win[0] = false`. With no stones the player to move cannot move and loses.
4. Order to fill: `s` from 1 to `n`; every move goes to a smaller pile.
5. Read the answer: `win[n]` tells whether the first player wins.
--think
- Signal: "two players", "optimal play", "who wins", "last to move wins" or loses. Check the rule for who loses when stuck (normal play: the player unable to move loses).
- Three useful pictures: winning and losing labels (this lesson); the score difference version (the state stores the best lead over the opponent for the player to move, `diff = max(gain - diff_of_next_state)`, used in coin-pick games on a range); and Sprague-Grundy numbers, which add up independent games with XOR.
- Patterns often repeat with a period, so compute a small table, find the pattern, and skip the DP. Check it with the table, never just trust it.
- With a more complex position, memoize on the full position (a bitmask of items left, a pair of indexes of the range left).
- Neighbours: interval DP (score-difference version on ranges), bitmask DP (position as a set), memoization.
- Pitfalls: treating "opponent wins" and "I lose" inconsistently; forgetting that the opponent also plays optimally (so use the minimising choice for them, via the negation); a wrong base case that flips every label.
--cost
Time O(n times number of allowed moves). Space O(n).
--java
static boolean firstPlayerWins(int n, int[] moves) {
    boolean[] win = new boolean[n + 1];          // win[0] = false: cannot move
    for (int s = 1; s <= n; s++)
        for (int m : moves)
            if (m <= s && !win[s - m]) { win[s] = true; break; }  // hand over a loss
    return win[n];
}
--py

    return win[n]

    return win[n];

### mqdp
--idea
Some DP transitions take the best value over a sliding window of earlier states: `dp[i] = a[i] + max(dp[i-k .. i-1])`. Scanning the window each time costs O(k) per state. A monotonic queue (a deque, a queue you can add to and remove from at both ends, that keeps its values in sorted order) gives the window maximum in O(1) amortised.
The example is a jump game: you start at index 0, each jump moves forward 1 to `k` places, you collect the number at every index you land on, and you must end at the last index. Find the best total. The best total ending at `i` is `a[i]` plus the best among the last `k` states.
--build
1. State: `dp[i]` is the best total of a path from index 0 that ends exactly at index `i`.
2. Transition: `dp[i] = a[i] + max(dp[j])` over `j` from `i - k` to `i - 1` (only valid indexes). The window maximum comes from the deque.
3. Base case: `dp[0] = a[0]`, and the deque starts holding index 0.
4. The deque holds indexes whose `dp` values are strictly decreasing from front to back. The front is always the window maximum.
5. Order to fill: for `i` from 1 to `n - 1`: (a) pop from the front while the front index is less than `i - k` (it left the window); (b) `dp[i] = a[i] + dp[front]`; (c) pop from the back while `dp[back] <= dp[i]` (those can never beat `i`, which is newer and at least as good); (d) push `i` at the back.
6. Read the answer: `dp[n - 1]`.
--think
- Signal: the transition takes a min or max over a window of fixed width of previous states (`dp[i - k .. i - 1]`), often with a cost depending only on `i`. For sums use prefix sums instead. For other shapes of range, think segment tree or the convex hull trick.
- Why popping from the back is safe: if a newer state `i` is at least as good as an older state `j`, then `j` leaves the window earlier and is never better, so it can never be the maximum again. Keeping the deque sorted is what makes the front the answer.
- Every index is pushed once and popped at most once, so the total work is O(n), not O(n times k).
- Store indexes, not values, so you can tell when the front has left the window.
- Neighbours: DP with prefix sums (sum windows), sliding window maximum (the same deque without a DP), constrained subsequence sum (here you may also start fresh, so `dp[i] = a[i] + max(0, window max)`).
- Pitfalls: popping the front with `< i - k` versus `<= i - k` (off by one: the window is `i - k` to `i - 1`, so an index `i - k` is still allowed); using `<` instead of `<=` when popping the back (harmless but keeps duplicates); forgetting that the queue must be popped before reading its front.
--cost
Time O(n). Space O(n) for `dp`, O(k) for the deque.
--java
static long jumpGame(int[] a, int k) {
    int n = a.length;
    long[] dp = new long[n];
    dp[0] = a[0];
    ArrayDeque<Integer> dq = new ArrayDeque<>();
    dq.addLast(0);
    for (int i = 1; i < n; i++) {
        while (dq.peekFirst() < i - k) dq.pollFirst();       // left the window
        dp[i] = a[i] + dp[dq.peekFirst()];                   // front = window maximum
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) dq.pollLast();   // dominated
        dq.addLast(i);
    }
    return dp[n - 1];
}
--py
from collections import deque

def jump_game(a, k):
    n = len(a)
    dp = [0] * n
    dp[0] = a[0]
    dq = deque([0])
    for i in range(1, n):
        while dq[0] < i - k:                     # left the window
            dq.popleft()
        dp[i] = a[i] + dp[dq[0]]                 # front = window maximum
        while dq and dp[dq[-1]] <= dp[i]:        # dominated
            dq.pop()
        dq.append(i)
    return dp[n - 1]
--cpp
long long jumpGame(const vector<int>& a, int k) {
    int n = a.size();
    vector<long long> dp(n, 0);
    dp[0] = a[0];
    deque<int> dq = {0};
    for (int i = 1; i < n; i++) {
        while (dq.front() < i - k) dq.pop_front();           // left the window
        dp[i] = a[i] + dp[dq.front()];                       // front = window maximum
        while (!dq.empty() && dp[dq.back()] <= dp[i]) dq.pop_back();   // dominated
        dq.push_back(i);
    }
    return dp[n - 1];
}

### wildcard
--idea
Wildcard matching asks whether a text matches a pattern where `?` matches any single character and `*` matches any run of characters, including none. Check "abcd" against "a*d": yes, `*` swallows "bc". The table is the same as for the two-sequence DP: rows are prefixes of the text and columns are prefixes of the pattern.
The difficulty is `*`, which can stand for any length. The trick is to see that a `*` either matches nothing (drop it from the pattern) or eats one more text character and stays available for the next one (drop a text character, keep the `*`).
--build
1. State: `ok[i][j]` is 1 when the first `i` characters of the text `s` match the first `j` characters of the pattern `p`, and 0 otherwise.
2. Transition if `p[j-1]` is `*`: `ok[i][j] = ok[i][j-1]` (the star matches nothing) or, when `i > 0`, `ok[i-1][j]` (the star eats `s[i-1]` and stays). Transition for any other pattern character: when `i > 0` and (`p[j-1]` is `?` or equals `s[i-1]`), `ok[i][j] = ok[i-1][j-1]`; otherwise 0.
3. Base case: `ok[0][0] = 1` (empty matches empty). `ok[0][j] = ok[0][j-1]` if `p[j-1]` is `*` and 0 otherwise (only stars can match an empty text).
4. Order to fill: `i` from 0 to `n`, and `j` from 1 to `m`. Each cell uses the left cell, the upper cell, and the diagonal. The table rows come from the code piece `newTable(m, 0)`.
5. Read the answer: `ok[n][m] == 1`.
--think
- Signal: a pattern with wildcards matched against a whole string. The full regular expression version (with `.` and `x*` meaning zero or more of `x`) has the same table; only the star transition changes: `x*` can match zero copies (`ok[i][j-2]`) or eat one `x` and stay (`ok[i-1][j]` when `s[i-1]` matches `x`).
- Decide star rules first: here `*` is its own token matching any sequence. In regular expressions `*` binds to the previous character. Mixing them up is the most common mistake.
- A greedy two-pointer method also exists for this wildcard version (remember the last star and backtrack), with O(n times m) worst case and O(1) memory, but the table is easier to get right and extends to other rules.
- Neighbours: edit distance and LCS (same table), distinct subsequences, KMP for patterns with no wildcards.
- Pitfalls: forgetting that a pattern of only stars matches the empty text (the base row); using `ok[i-1][j]` when `i = 0`; swapping rows and columns.
--cost
Time O(n times m). Space O(n times m), or O(m) with a rolling row.
--java
static boolean wildcard(String s, String p) {
    int n = s.length(), m = p.length();
    long[][] ok = new long[n + 1][];
    for (int i = 0; i <= n; i++) ok[i] = newTable(m, 0);     // 0 = no match yet
    ok[0][0] = 1;                                // empty matches empty
    for (int i = 0; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            char c = p.charAt(j - 1);
            if (c == '*')                        // star: match nothing, or eat one char
                ok[i][j] = (ok[i][j - 1] == 1 || (i > 0 && ok[i - 1][j] == 1)) ? 1 : 0;
            else if (i > 0 && (c == '?' || c == s.charAt(i - 1)))
                ok[i][j] = ok[i - 1][j - 1];     // one char matched
        }
    return ok[n][m] == 1;
}

### distinctsub
--idea
Count how many ways the string `t` appears as a subsequence of the string `s` (a subsequence keeps the order but may skip characters, and two ways are different when they use different positions). In "rabbbit" the word "rabbit" appears 3 times, depending on which of the three b's is skipped.
Look at the last character of `s`. Either it is not used (the ways are those within the shorter `s`), or, if it equals the last character of `t`, it is used to match that character (the ways are those matching the shorter `t` inside the shorter `s`). Add the two.
--build
1. State: `dp[i][j]` is the number of ways the first `j` characters of `t` appear as a subsequence of the first `i` characters of `s`, modulo `M = 1,000,000,007` (the count grows huge).
2. Transition: `dp[i][j] = dp[i-1][j]` (skip `s[i-1]`), plus `dp[i-1][j-1]` when `s[i-1] == t[j-1]` (use it). The addition is the code piece `addMod`.
3. Base case: `dp[i][0] = 1` for every `i` (the empty `t` appears exactly once: choose nothing), and `dp[0][j] = 0` for `j > 0`. Rows come from the code piece `newTable(m, 0)`.
4. Order to fill: `i` from 1 to `n`, `j` from 1 to `m`.
5. Read the answer: `dp[n][m]`.
--think
- Signal: "number of subsequences equal to", "in how many ways can this word be formed". Two strings and a count: it is the same table as LCS and edit distance with `+` instead of `max`.
- The state asks "how many ways using only the first `i` of `s`". The transition is "last character used or not". Say it that way and the table writes itself.
- Related count problems: number of distinct subsequences of one string (a one-dimensional DP with the last occurrence of each letter), counting palindromic subsequences, and counting ways to partition.
- Memory: only the previous row is needed, but if you update one row in place go from `j = m` downward, otherwise `dp[j-1]` is already overwritten.
- Pitfalls: forgetting the modulus; base row confusion (empty target is 1, empty source with a non-empty target is 0); using `i`, `j` as string indexes instead of `i-1`, `j-1`.
--cost
Time O(n times m). Space O(m) with a rolling row, O(n times m) for the plain table.
--java
static int distinctSubseq(String s, String t) {
    final int M = 1_000_000_007;
    int n = s.length(), m = t.length();
    long[][] dp = new long[n + 1][];
    for (int i = 0; i <= n; i++) { dp[i] = newTable(m, 0); dp[i][0] = 1; }   // empty t: 1 way
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            int use = s.charAt(i - 1) == t.charAt(j - 1) ? (int) dp[i - 1][j - 1] : 0;
            dp[i][j] = addMod((int) dp[i - 1][j], use, M);   // skip, plus use
        }
    return (int) dp[n][m];
}

### digit
--idea
Digit DP counts the numbers up to `N` that have some property of their digits, by building each number one digit at a time from the left. The example: count the integers from 0 to `N` whose digits add up to `S`. There can be billions of numbers, so we cannot test them one by one.
The picture: numbers up to `N` form a tree of digit choices. At each position, while the digits chosen so far equal the start of `N`, you are "tight": the next digit cannot exceed `N`'s digit. As soon as you pick a smaller digit, you are "free": every later digit can be 0 to 9, and the count then depends only on the position and what the property still needs. Those free states repeat a lot, so we remember them.
--build
Small steps:
1. Split `N` into its digits `d[0..len-1]`, most significant first. This is the code piece `digits(N)`.
2. State: `f(pos, sum, tight)` is how many ways to fill the digits from position `pos` to the end so the final digit sum is exactly `S`, given the digits so far add to `sum`. `tight` is true if the digits so far equal the first `pos` digits of `N`.
3. Transition: the digit at `pos` can be `0` up to `limit`, where `limit = d[pos]` if `tight`, otherwise 9. For each digit `x`, add `f(pos + 1, sum + x, tight and x == limit)`.
4. Base case: at `pos == len`, return 1 if `sum == S`, else 0. Also return 0 early when `sum > S` (digits are not negative, so it can only grow).
5. Memory: only the non-tight states are stored, in `memo[pos][sum]`, because tight states occur once per position. The table is made with the code piece `newTable(S, -1)` for each position, where -1 means "not computed".
6. Read the answer: `f(0, 0, true)`. It counts every number from 0 to `N` with leading zeros as part of the number, which does not change a digit sum, so the count is right.
What must hold: the property must be buildable digit by digit with a small summary (here the running sum, at most `S`). If the summary can be large (the whole number), digit DP does not apply.
--think
- Signal: "count numbers in a range with a digit property" (digit sum, no two equal neighbours, contains a digit, divisible by `k` with the remainder as the state). Ranges `[L, R]` are answered as `count(R) - count(L - 1)`.
- The state is a position, a small summary of the digits so far, and the tight flag. Add a "started" flag when leading zeros matter (for example, "no repeated digits" must not count the leading zeros as digits).
- Why only the free states need memory: a free state's answer depends only on `(pos, summary)`. A tight state is a single path, visited once per position.
- Neighbours: state machine DP (the summary is the mode), counting DP over positions, inclusion-exclusion on digits.
- Pitfalls: forgetting the tight flag (then you count numbers above `N`); memoizing tight states with the wrong key; `N = 0`; counting from 0 vs from 1 (subtract the empty number when the property counts it); overflow of counts (use `long`).
--cost
Time O(digits times S times 10). Space O(digits times S).
--java
static long countDigitSum(long N, int S) {
    int[] d = digits(N).stream().mapToInt(Integer::intValue).toArray();
    long[][] memo = new long[d.length][];
    for (int i = 0; i < d.length; i++) memo[i] = newTable(S, -1);   // -1 = not computed
    return digitRec(0, 0, true, d, S, memo);
}
static long digitRec(int pos, int sum, boolean tight, int[] d, int S, long[][] memo) {
    if (sum > S) return 0;
    if (pos == d.length) return sum == S ? 1 : 0;
    if (!tight && memo[pos][sum] != -1) return memo[pos][sum];
    int limit = tight ? d[pos] : 9;
    long total = 0;
    for (int x = 0; x <= limit; x++)
        total += digitRec(pos + 1, sum + x, tight && x == limit, d, S, memo);
    if (!tight) memo[pos][sum] = total;          // only free states are remembered
    return total;
}

### reroot
--idea
Rerooting computes, for every node of a tree, an answer as if that node were the root. Doing the tree DP separately from each root costs O(n squared). Rerooting does it in two passes: first compute the usual answer with one fixed root (from the leaves up), then walk down and, for each child, derive its answer from its parent's full answer by removing the child's part and adding "everything else" as a new subtree.
The example: for every node, the sum of distances from it to all other nodes. With root 0, `down[v]` is the sum of distances from `v` to the nodes in its own subtree. Moving the root from parent `p` to child `v`: the `size[v]` nodes in `v`'s subtree get one step closer, and the other `n - size[v]` nodes get one step further.
--build
Small steps:
1. Root the tree at node 0 and get a parent-before-child order (breadth-first), and each node's parent.
2. State (first pass): `size[v]` is the number of nodes in the subtree of `v`; `down[v]` is the sum of distances from `v` to the nodes in its subtree.
3. First pass, children before parents (reverse order): `size[p] += size[v]` and `down[p] += down[v] + size[v]` (each of the `size[v]` nodes is one step further from `p` than from `v`).
4. State (second pass): `ans[v]` is the sum of distances from `v` to all `n` nodes. Base case: `ans[0] = down[0]`.
5. Second pass, parents before children (the order itself): `ans[v] = ans[p] - size[v] + (n - size[v])`, which is `ans[p] + n - 2 * size[v]`. The first `size[v]` nodes got closer by 1, the remaining `n - size[v]` got further by 1.
6. Read the answer: the array `ans`.
What must hold: the combine step must be reversible. Here the answer is a sum, so "remove the child's part" is a subtraction. When the answer is a max (for example the longest path from each node), you cannot subtract; instead keep, for each node, the best and second-best child contributions, or prefix and suffix maxima over the children, so "everything except this child" is available in O(1).
--think
- Signal: "for every node as the root", "the farthest node from each node", "sum of distances to all nodes", "the best centre of the tree". A hint is that the problem would be a plain tree DP if the root were fixed.
- Plan: (1) define the tree DP for a fixed root; (2) ask what the parent's value looks like from the child's side (the "up" value, the answer for the tree with the child's subtree removed); (3) combine the child's own subtree with the up value.
- Cost control: the combination for each child must not loop over all siblings, or it becomes quadratic on a star. Use sums with subtraction, or prefix and suffix arrays over the children.
- Neighbours: tree DP (the first pass), centroid decomposition (different technique for paths), binary lifting, Euler tour.
- Pitfalls: mixing which side `size` counts; recursion depth on deep trees (the order-based loops here avoid it); forgetting the up value in the max version; edges stored in one direction only.
--cost
Time O(n). Space O(n).
--java
static long[] sumDistances(int n, int[][] edges) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); }
    int[] parent = new int[n], order = new int[n];
    parent[0] = -1;
    int head = 0, tail = 0;
    order[tail++] = 0;
    while (head < tail) {                        // parents before children
        int u = order[head++];
        for (int v : adj.get(u))
            if (v != parent[u]) { parent[v] = u; order[tail++] = v; }
    }
    long[] size = new long[n], down = new long[n], ans = new long[n];
    Arrays.fill(size, 1);
    for (int i = n - 1; i > 0; i--) {            // pass 1: children before parents
        int v = order[i], p = parent[v];
        size[p] += size[v];
        down[p] += down[v] + size[v];
    }
    ans[0] = down[0];
    for (int i = 1; i < n; i++) {                // pass 2: parents before children
        int v = order[i], p = parent[v];
        ans[v] = ans[p] + n - 2 * size[v];
    }
    return ans;
}

### dpopt
--idea
A DP optimisation is a trick that makes a slow DP fast by exploiting structure in the transition. Many DPs have the form `dp[i] = min over j of (dp[j] + cost(j, i))`, which takes O(n) per state and O(n squared) in total (or O(k times n squared) with `k` layers). If the best `j` moves in a predictable way as `i` grows, or `cost` has a special shape, most of that search is wasted.
This lesson is the map. The example problem: split an array of non-negative numbers into exactly `k` consecutive groups, and minimise the sum over groups of (group sum) squared. The plain DP below is the reference that every optimisation must agree with. The other lessons (divide and conquer, Knuth, convex hull trick, Aliens trick) make it faster.
--build
1. State: `dp[t][i]` is the least cost to split the first `i` numbers into exactly `t` groups.
2. Transition: `dp[t][i] = min over j from t-1 to i-1 of dp[t-1][j] + (pre[i] - pre[j])^2`. Here `pre` is the prefix sum array, so the last group is the numbers `j` to `i-1`, with sum `pre[i] - pre[j]`.
3. Base case: `dp[0][0] = 0`; every other `dp[0][i]` is infinity (zero groups cannot cover numbers).
4. Order to fill: `t` from 1 to `k` (layers), and for each layer `i` from `t` to `n`.
5. Read the answer: `dp[k][n]`. Only the previous layer is ever needed, so two rows are enough.
6. Choosing an optimisation (look at the transition `dp[i] = min_j dp[j] + cost(j, i)`):
 - If `cost` obeys the quadrangle inequality (it is "Monge"), the best `j` never moves left as `i` grows: use divide and conquer optimisation (layers) or Knuth optimisation (interval DP).
 - If `cost(j, i)` expands into `slope(j) * x(i) + intercept(j) + something(i)`, the choice of `j` is "the best line at the point `x(i)`": use the convex hull trick.
 - If the answer as a function of the number of groups `k` is convex, drop the layer index: add a penalty per group and binary search it (Aliens trick).
 - If the window of allowed `j` slides, use a monotonic queue.
--think
- Signal: a DP that is correct but too slow, with a transition that minimises over a range of earlier states of the same layer, and a cost with a clean algebraic form (squares, distances, sums of ranges).
- First write the plain DP and test the fast one against it on small random inputs. This is the single most useful habit: optimisations fail silently when a condition is almost, but not quite, true.
- The conditions to check: (1) monotone opt: let `opt(i)` be the best `j` for `i`; is `opt(i) <= opt(i+1)`? Test it by brute force on random data. (2) Quadrangle inequality: for `a <= b <= c <= d`, `cost(a,c) + cost(b,d) <= cost(a,d) + cost(b,c)`; it implies monotone opt. Squares of range sums of non-negative numbers satisfy it. (3) Convexity in `k`: the best cost with `k` groups has non-decreasing differences.
- Do not apply an optimisation because it is famous; apply it because the structure says it holds.
- Neighbours: interval DP (Knuth), bitmask DP (none of these apply), monotonic queue DP (a window).
- Pitfalls: allowing empty groups; counting layers from 0 or 1 inconsistently; infinity added to costs and overflowing; assuming monotone opt when cost can be negative or the numbers are not non-negative.
--cost
Plain DP: O(k times n squared) time, O(n) space with two rows. The optimisations bring it to about O(k times n log n), O(n squared), O(n) or O(n log C), depending on which one fits.
--java
static long splitSquares(int[] a, int k) {
    int n = a.length;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    long INF = Long.MAX_VALUE / 4;
    long[] prev = new long[n + 1];
    Arrays.fill(prev, INF);
    prev[0] = 0;                                 // zero groups cover zero numbers
    for (int t = 1; t <= k; t++) {
        long[] cur = new long[n + 1];
        Arrays.fill(cur, INF);
        for (int i = t; i <= n; i++)
            for (int j = t - 1; j < i; j++) {    // last group is numbers j..i-1
                long s = pre[i] - pre[j];
                cur[i] = Math.min(cur[i], prev[j] + s * s);
            }
        prev = cur;
    }
    return prev[n];
}

### dcopt
--idea
Divide and conquer optimisation speeds up a layered DP `cur[i] = min over j < i of prev[j] + cost(j, i)` from O(n squared) per layer to O(n log n) per layer. It needs one property: the best split point `opt(i)` never moves left as `i` grows (`opt(i) <= opt(i+1)`).
Given that, solve the middle `i` by trying every `j` in the allowed range. Then everything to its left can only use `j` at most `opt(mid)`, and everything to its right only `j` at least `opt(mid)`. Recurse on both halves with the narrowed ranges. Each level of recursion scans about `n` candidates in total, and there are about `log n` levels.
Example: split numbers into exactly `k` consecutive groups minimising the sum of (group sum) squared.
--build
Small steps:
1. Prefix sums `pre[0..n]`, so the cost of a group of numbers `j..i-1` is `cost(j, i) = (pre[i] - pre[j])^2`.
2. State: `prev[j]` is the best cost to split the first `j` numbers into `t - 1` groups, and `cur[i]` the same with `t` groups. Base case: `prev[0] = 0` and `prev[j] = INF` for `j > 0` (the layer with zero groups).
3. Transition: `cur[i] = min over j in [t-1, i-1] of prev[j] + cost(j, i)`.
4. Define `compute(lo, hi, optLo, optHi)`: fill `cur[lo..hi]` knowing the best `j` for each of these `i` lies in `[optLo, optHi]`.
5. In `compute`: if `lo > hi` stop. Let `m` be the middle of `lo` and `hi` (the code piece `mid`). Scan `j` from `optLo` to `min(m - 1, optHi)`, take the best, call it `best`. Set `cur[m]` to its value.
6. Recurse: `compute(lo, m - 1, optLo, best)` and `compute(m + 1, hi, best, optHi)`.
7. Order to fill: layers `t` from 1 to `k`; each layer starts with `compute(t, n, t - 1, n - 1)`.
8. Read the answer: `cur[n]` after layer `k`.
What must hold: the best `j` is monotone, `opt(i) <= opt(i+1)`. This follows from the quadrangle inequality `cost(a,c) + cost(b,d) <= cost(a,d) + cost(b,c)` for `a <= b <= c <= d`. For `(S[r] - S[l])^2` with non-negative numbers it is true, because squaring is convex and the prefix sums only grow. On ties, choose the first best `j` consistently.
--think
- Signal: a layered DP (`k` groups, `k` stops, `k` batches) where the transition scans an earlier layer with a cost like the square of a range sum, a distance penalty, or a batch set-up cost.
- Prove or test the monotonicity first. Write the plain DP, record `opt(i)` for random small inputs, and check that it never goes down.
- Why recursion over `i` and ranges over `j`: the middle `i` fixes a pivot `best`, which cuts the `j` ranges of the two halves. That is why the total scan per level is O(n).
- It does not work for every layered DP. If `cost` can be negative in certain ways, or depends on both layers, `opt` may jump around.
- Neighbours: Knuth optimisation (same monotone idea for interval DPs), the convex hull trick (when the cost expands into lines), Aliens trick (removes the layers), monotonic queue.
- Pitfalls: using the range `[optLo, optHi]` inclusively on both sides but clipping `j` below `i`; a wrong base layer (infinity entries in `prev` are fine only if the `j` lower bound is `t - 1`); recursion depth is only about `log n`, which is fine.
--cost
Time O(k times n log n). Space O(n) plus the recursion depth O(log n).
--java
static long dcSplit(int[] a, int k) {
    int n = a.length;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    long INF = Long.MAX_VALUE / 4;
    long[] prev = new long[n + 1];
    Arrays.fill(prev, INF);
    prev[0] = 0;
    for (int t = 1; t <= k; t++) {
        long[] cur = new long[n + 1];
        Arrays.fill(cur, INF);
        dcCompute(t, n, t - 1, n - 1, prev, cur, pre);
        prev = cur;
    }
    return prev[n];
}
static void dcCompute(int lo, int hi, int optLo, int optHi, long[] prev, long[] cur, long[] pre) {
    if (lo > hi) return;
    int m = mid(lo, hi);                         // code piece: middle without overflow
    long best = Long.MAX_VALUE;
    int bestJ = optLo;
    for (int j = optLo; j <= Math.min(m - 1, optHi); j++) {
        long s = pre[m] - pre[j];
        long v = prev[j] + s * s;
        if (v < best) { best = v; bestJ = j; }   // first best wins ties
    }
    cur[m] = best;
    dcCompute(lo, m - 1, optLo, bestJ, prev, cur, pre);
    dcCompute(m + 1, hi, bestJ, optHi, prev, cur, pre);
}

def dc_split(a, k):

    for i in range(n):
        pre[i + 1] = pre[i] + a[i]

    prev = [INF] * (n + 1)

### knuth
--idea
Knuth optimisation speeds up an interval DP of the form `dp[i][j] = min over k in [i, j-1] of dp[i][k] + dp[k+1][j] + w(i, j)` from O(n cubed) to O(n squared). The split point `k` is not searched across the whole range: it is limited between the best split of the range one shorter on the right and the best split of the range one shorter on the left.
The example is merging adjacent piles at the cost of their combined size (the same as the interval DP lesson). Let `opt[i][j]` be the best split for the range `i..j`. Knuth's rule: `opt[i][j-1] <= opt[i][j] <= opt[i+1][j]`.
--build
Small steps:
1. Prefix sums `pre`, with `w(i, j) = pre[j+1] - pre[i]` (the total of piles `i..j`).
2. State: `dp[i][j]` is the least cost to merge piles `i..j` into one pile, and `opt[i][j]` the split point `k` that achieved it (left block `i..k`, right block `k+1..j`).
3. Transition: `dp[i][j] = w(i, j) + min over k from opt[i][j-1] to min(opt[i+1][j], j-1) of dp[i][k] + dp[k+1][j]`. Record the best `k` in `opt[i][j]`.
4. Base case: `dp[i][i] = 0` and `opt[i][i] = i`. The tables come from the code piece `newTable(n - 1, 0)` (rows of `n` zeros).
5. Order to fill: by range length from 2 to `n`, so both `opt[i][j-1]` and `opt[i+1][j]` (shorter ranges) already exist.
6. Read the answer: `dp[0][n-1]`.
What must hold: (a) the quadrangle inequality, `w(a,c) + w(b,d) <= w(a,d) + w(b,c)` for `a <= b <= c <= d`; (b) monotonicity of `w`, `w(b,c) <= w(a,d)` for `a <= b <= c <= d`. Range sums of non-negative numbers satisfy both. Together they prove `opt[i][j-1] <= opt[i][j] <= opt[i+1][j]`.
Why it is O(n squared): for a fixed difference `j - i = d`, the scan ranges of consecutive `i` are `[opt[i][j-1], opt[i+1][j]]`, and they chain end to start (`opt[i+1][j]` is the left end of the next range), so they add up to about `n` for each `d`. With `n` values of `d`, the total is O(n squared).
--think
- Signal: an interval DP with a cubic split loop and a cost `w(i, j)` that depends only on the range (sums, lengths), such as merging piles, optimal binary search tree, and some cutting problems.
- Always test the speed-up against the cubic version on random inputs. If the answers differ, a condition fails and the optimisation is not valid for that cost.
- Same idea as divide and conquer optimisation, with the monotone `opt` replaced by the sandwich `opt[i][j-1] <= opt[i][j] <= opt[i+1][j]`.
- Neighbours: interval DP (the slow form), optimal binary search tree (Knuth applies), divide and conquer optimisation (layered DPs), Garsia-Wachs (merging piles in O(n log n)).
- Pitfalls: scanning `k` up to `opt[i+1][j]` without clipping to `j - 1` (the split must leave a non-empty right block); wrong order of filling; using it when the cost is not Monge (for example, costs that depend on the split point itself).
--cost
Time O(n squared). Space O(n squared).
--java
static long mergeKnuth(int[] a) {
    int n = a.length;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    long[][] dp = new long[n][], opt = new long[n][];
    for (int i = 0; i < n; i++) {
        dp[i] = newTable(n - 1, 0);
        opt[i] = newTable(n - 1, 0);
        opt[i][i] = i;                           // a single pile splits at itself
    }
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            long best = Long.MAX_VALUE;
            int bestK = i;
            for (int k = (int) opt[i][j - 1]; k <= Math.min(opt[i + 1][j], j - 1); k++) {
                long v = dp[i][k] + dp[k + 1][j];
                if (v < best) { best = v; bestK = k; }
            }
            dp[i][j] = best + pre[j + 1] - pre[i];
            opt[i][j] = bestK;
        }
    return dp[0][n - 1];
}

### cht
--idea
The convex hull trick (CHT) speeds up DPs of the form `dp[i] = min over j < i of (m_j * x_i + b_j)`: each earlier state `j` acts as a line `y = m_j * x + b_j`, and each new state asks "which line is lowest at the point `x_i`?". The lower envelope (the lowest line at every `x`) is a convex shape, and only a few lines ever appear on it. Keeping just those lines turns an O(n) search into O(1) amortised.
Example (the "frog" problem): stones at increasing heights `h`. Jumping from stone `j` to `i` costs `(h[i] - h[j])^2 + C`. Find the cheapest way from stone 0 to the last stone. Expanding the square: `dp[i] = h[i]^2 + C + min over j of ( -2*h[j] * h[i] + (dp[j] + h[j]^2) )`. Each `j` is a line with slope `-2*h[j]` and intercept `dp[j] + h[j]^2`, queried at `x = h[i]`.
--build
Small steps:
1. State: `dp[i]` is the least cost to reach stone `i`. Base case: `dp[0] = 0`.
2. Line for stone `j`: slope `m_j = -2 * h[j]`, intercept `b_j = dp[j] + h[j]^2`. Its value at `x` is `m_j * x + b_j`.
3. Transition: `dp[i] = h[i]^2 + C + min over lines of value at x = h[i]`.
4. Keep the lines in a deque (arrays `M`, `B` with a front and a back index). Order to fill: `i` from 1 to `n - 1`; after computing `dp[i]`, add the line of `i`.
5. Adding a line: slopes arrive strictly decreasing (heights increase). While the deque has two or more lines and the newest-but-one line `l2` is never the lowest once the new line `l3` exists, remove `l2`. With `l1` before `l2`, test the signed area (the code piece `cross`) of the vectors `l2 - l1` and `l3 - l1` in the (slope, intercept) plane: `cross(m2-m1, b2-b1, m3-m1, b3-b1) >= 0` means `l2` is useless.
6. Query at `x = h[i]`: the queries increase, so while the second line from the front is at least as good as the front line at `x`, pop the front. The answer line is then the front.
7. Read the answer: `dp[n - 1]`.
What must hold: the slopes are added in sorted order (here decreasing) and the query points are sorted (here increasing); then both ends of the deque only move one way, and the total is O(n). If queries are not sorted, binary search the deque; if the slopes are not sorted, use a Li Chao tree (a segment tree over `x` that stores one line per node).
--think
- Signal: after expanding the cost, you get a product of a quantity from `j` and a quantity from `i` (`h[j] * h[i]`, `s[j] * t[i]`), plus parts that depend only on `j` or only on `i`. Costs like squared distances, "start-up cost times the remaining count", and batch problems.
- Write the transition on paper, move everything depending only on `i` outside the min, and read off slope and intercept for each `j`.
- Compare against the O(n squared) DP on random inputs.
- Min versus max: for a maximum, negate the slopes and intercepts (and flip the answer), or flip the sign in the test.
- Integer overflow: the cross product multiplies two differences, which can reach about 10 to the 18 times 10 to the 18; use `long double` or `__int128` when values are large, or compare fractions of the intersections carefully.
- Neighbours: divide and conquer optimisation (also monotone, no algebra needed), Li Chao tree (any order), monotonic queue DP.
- Pitfalls: equal slopes (keep the lower intercept; here slopes are strictly decreasing because heights are strictly increasing); mixing the roles of `x` and slope; popping the wrong end.
--cost
Time O(n) when slopes and queries are sorted. Space O(n).
--java
static long frog(long[] h, long C) {
    int n = h.length;
    long[] dp = new long[n];
    long[] M = new long[n], B = new long[n];     // lines kept in the deque M[front..back]
    int front = 0, back = 0;
    M[0] = -2 * h[0]; B[0] = h[0] * h[0];        // line of stone 0 (dp[0] = 0)
    back = 1;
    for (int i = 1; i < n; i++) {
        long x = h[i];
        while (back - front >= 2 && M[front + 1] * x + B[front + 1] <= M[front] * x + B[front])
            front++;                             // the next line is at least as low
        dp[i] = x * x + C + M[front] * x + B[front];
        long m3 = -2 * h[i], b3 = dp[i] + h[i] * h[i];
        while (back - front >= 2) {
            long m1 = M[back - 2], b1 = B[back - 2], m2 = M[back - 1], b2 = B[back - 1];
            if (cross(m2 - m1, b2 - b1, m3 - m1, b3 - b1) >= 0) back--;   // l2 never lowest
            else break;
        }
        M[back] = m3; B[back] = b3; back++;
    }
    return dp[n - 1];
}

### aliens
--idea
The Aliens trick (also called Lagrangian relaxation or lambda optimisation) removes the "exactly `k` pieces" dimension from a DP. Suppose `f(k)` is the best cost of splitting into exactly `k` pieces, and `f` is convex in `k` (the savings from each extra piece keep shrinking). Instead of tracking `k`, charge a penalty `lambda` for every piece used and solve the plain problem "minimise cost plus `lambda` times the number of pieces". A bigger `lambda` makes fewer pieces worthwhile. Binary search `lambda` until the best plan uses exactly `k` pieces.
Example: split numbers into exactly `k` consecutive groups, minimising the sum of (group sum) squared. With the penalty, the DP loses its layer index.
--build
Small steps:
1. Inner problem for a fixed `lambda`: `g[i]` is the least value of (cost + `lambda` times pieces) for the first `i` numbers, and `cnt[i]` is the number of pieces in that best plan (on a tie in value, take the smaller count).
2. Transition: `g[i] = min over j < i of g[j] + (pre[i] - pre[j])^2 + lambda`, with `cnt[i] = cnt[j] + 1` for the chosen `j`. Base case: `g[0] = 0`, `cnt[0] = 0`. Order: `i` from 1 to `n`. This is O(n squared) here; use another optimisation inside to make it faster.
3. Outer search: `cnt` (with smallest-count tie-breaking) is non-increasing as `lambda` grows. Find the smallest `lambda` (an integer, since all costs are integers) in `[0, hi]` with `cnt[n] <= k`, using the code piece `mid` for the middle. Choose `hi` big enough that one piece is optimal (for example `total^2 + 1`).
4. Why this `lambda` works: at it, the plan with the fewest pieces has at most `k` pieces and the plans with the most pieces at this `lambda` (tie) have at least `k`, since one step smaller `lambda` had more than `k`. By convexity, every count between them is also optimal at this `lambda`, including `k`.
5. Read the answer: `f(k) = g[n] - lambda * k`. We subtract the penalty that we added for `k` pieces. Use `k` here, not `cnt[n]`.
What must hold: `f(k)` is convex in `k` (the second difference is non-negative). Then the lower convex hull of `f` touches every point `(k, f(k))`, and each `lambda` picks one of them (or a tied range). If `f` is not convex, some `k` is skipped and the method gives wrong answers. Also `k` must not exceed `n`.
--think
- Signal: "exactly `k` pieces / groups / edges / trips" with a large `k`, a DP over positions and the layer count, and a cost that feels convex (squares, distances, matroid-like choices). Also "choose exactly `k` disjoint subarrays with the largest sum" and similar.
- Test convexity first by brute force: compute `f(1)` to `f(n)` on random data, and check `f(k-1) + f(k+1) >= 2 f(k)`.
- Handling ties: the standard safe way is the one used here: count the fewest pieces on ties, search the smallest `lambda` with `cnt <= k`, and compute `g[n] - lambda * k`. Using the most pieces instead needs the mirrored search.
- If costs are real numbers, binary search `lambda` over reals with a fixed number of rounds, and read the answer with the same formula.
- Neighbours: divide and conquer optimisation (keeps the layers), the convex hull trick (speeds up the inner DP), binary search on the answer (a different search, on the value).
- Pitfalls: using `cnt[n]` instead of `k` in the final formula; wrong tie-break; `lambda` range too small (then one piece is never optimal) or too large (overflow); not testing convexity.
--cost
Time O(inner DP times log(range of lambda)). Here O(n squared log(total squared)). Space O(n).
--java
static long aliensSplit(int[] a, int k) {
    int n = a.length;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    int lo = 0, hi = (int) (pre[n] * pre[n]) + 1;     // assumes total squared fits in an int
    while (lo < hi) {                            // smallest lambda with cnt <= k
        int lam = mid(lo, hi);                   // code piece
        if (aliensInner(pre, lam)[1] <= k) hi = lam; else lo = lam + 1;
    }
    return aliensInner(pre, lo)[0] - (long) lo * k;
}
static long[] aliensInner(long[] pre, int lam) {
    int n = pre.length - 1;
    long[] g = new long[n + 1], cnt = new long[n + 1];
    for (int i = 1; i <= n; i++) {
        g[i] = Long.MAX_VALUE;
        for (int j = 0; j < i; j++) {
            long s = pre[i] - pre[j], v = g[j] + s * s + lam;
            if (v < g[i] || (v == g[i] && cnt[j] + 1 < cnt[i])) { g[i] = v; cnt[i] = cnt[j] + 1; }
        }
    }
    return new long[]{g[n], cnt[n]};
}

### matdp
--idea
Matrix exponentiation DP handles a DP whose next state is a fixed linear combination of the current state, when you need the state after a huge number of steps (like 10 to the 18). Write the state as a column vector `v`. One step is `v_next = T * v` for a fixed square matrix `T` (the transition matrix). Then `n` steps are `T^n * v`, and `T^n` is computed by repeated squaring in O(log n) matrix multiplications.
Example: count binary strings of length `n` with no two adjacent 1s, modulo 1,000,000,007. The state is `(e0, e1)`: how many valid strings end in 0, and how many end in 1. Appending 0 is always allowed, appending 1 only after a 0.
--build
Small steps:
1. State vector: `v = (e0, e1)`, the counts of valid strings of the current length ending in 0 and in 1.
2. Transition: `e0' = e0 + e1` (append 0 to anything), `e1' = e0` (append 1 only after a 0). As a matrix, `T = [[1, 1], [1, 0]]`, so `v' = T * v`.
3. Base case: for length 0 treat the empty string as ending in 0, so `v = (1, 0)`. (Then length 1 gives `(1, 1)`, which is right: "0" and "1".)
4. Order to fill: no table. Compute `P = T^n` with the code piece `matPow(T, n, M)` (repeated squaring, every product reduced modulo `M`).
5. Read the answer: the total after `n` steps is the sum of the entries of `P * v`. Since `v = (1, 0)`, that is `P[0][0] + P[1][0]`, taken modulo `M`.
Recipe for any linear recurrence: write `dp[i] = c1*dp[i-1] + ... + ck*dp[i-k]`; the state vector is `(dp[i-1], ..., dp[i-k])`; the top row of the matrix holds `c1..ck` and the rows below hold a shifted identity.
--think
- Signal: a linear recurrence (counting with fixed rules, no dependence on `i` itself) and `n` far too large to loop over (10 to the 9 or more), usually with an answer modulo a prime.
- Choose the state vector so that every quantity the next step needs is in it; add a constant `1` entry if the recurrence has a constant term. Then fill in the matrix row by row: row `r` says how to compute new entry `r` from the old ones.
- Cost is `k` cubed times log `n` for a `k` by `k` matrix, so keep `k` small (up to about 50 to 100).
- Variants: counting paths of exactly `n` edges in a graph (the matrix is the adjacency matrix), shortest paths of exactly `n` edges (use the min-plus product instead of the usual one), and the Fibonacci numbers.
- If `n` is small, a plain loop is simpler. If the transitions change with `i`, matrices do not apply directly.
- Neighbours: counting DP (the loop version), Fibonacci by fast doubling, Kitamasa or Berlekamp-Massey for very long recurrences.
- Pitfalls: forgetting the modulus inside the multiplication (overflow); wrong base vector; the identity matrix as the starting value of the power (the code piece does this); multiplying vector and matrix in the wrong order for non-symmetric matrices.
--cost
Time O(k cubed times log n). Space O(k squared).
--java
static long noAdjacentOnes(long n) {
    final long M = 1_000_000_007L;
    long[][] T = {{1, 1}, {1, 0}};               // v' = T * v, v = (ends in 0, ends in 1)
    long[][] P = matPow(T, n, M);                // code piece: T to the power n
    return (P[0][0] + P[1][0]) % M;              // start vector is (1, 0)
}

### incldp
--idea
Inclusion-exclusion counts objects that must satisfy a "nothing is missing" kind of condition by starting from an easy over-count and correcting it. A DP version applies the correction in a table: first compute the easy count for each smaller case, then subtract the parts that really belong to those smaller cases.
Example: count strings of length `n` over an alphabet of `m` letters that use every letter at least once (surjections). Easy count for `j` letters: any string over `j` chosen letters, `j^n`. But that includes strings missing some of the `j` letters. A string that uses exactly `i` of the `j` letters can be picked in `C(j, i)` ways of choosing which letters. So the strings using all `j` letters are `j^n` minus those using exactly `i < j` letters.
--build
1. State: `exact[j]` is the number of strings of length `n` that use every one of `j` given letters at least once (exactly those `j` letters), modulo `M = 1,000,000,007`.
2. Easy count: `all[j] = j^n`, the strings over `j` letters with no further condition. Compute it with a small modular power routine.
3. Transition: `exact[j] = all[j] - sum over i from 0 to j-1 of C(j, i) * exact[i]`. Each string over `j` letters uses exactly some subset of `i` of them, counted once; subtracting all the proper subsets leaves the ones using all `j`.
4. Base case: `exact[0] = 1` if `n == 0` (the empty string), else 0. With `j^n` computed as 1 for `n = 0`, the recurrence gives this automatically: `exact[0] = all[0] = 0^n`, which is 1 only when `n = 0`.
5. Order to fill: `j` from 0 to `m`. Binomials `C(j, i)` come from Pascal's triangle with the code piece `addMod` (`C[j][i] = C[j-1][i-1] + C[j-1][i]`).
6. Read the answer: `exact[m]`. Subtractions use the code piece `subMod`, so values never go negative.
--think
- Signal: "count objects where every one of several features appears", "no element is fixed or missing", "at least one of each", counting derangements, surjections, or colourings that use all colours, or counts of coprime pairs. The easy version (ignore the condition) is simple, and the exact version removes the bad cases.
- Two forms: the alternating sum `sum over k of (-1)^k C(m, k) (m-k)^n` (direct formula, O(m log n)), and the DP form used here, which generalises when the "easy count" for a subset is not a plain power (it may itself come from a table).
- For conditions over subsets of constraints that are each easy to ignore, enumerate the subsets of constraints (a bitmask) and add or subtract the count with those constraints ignored, by parity of the subset size. That is the other classic use.
- Neighbours: counting DP, bitmask DP, Mobius function inversions (inclusion-exclusion over divisors), SOS DP for subset sums.
- Pitfalls: signs (which parity adds); negative values after modular subtraction (add the modulus); computing binomials with division without a modular inverse (the triangle avoids it); `0^0`.
--cost
Time O(m squared) for the triangle and the sum, plus O(m log n) for the powers. Space O(m squared).
--java
static int surjections(int n, int m) {
    final int M = 1_000_000_007;
    int[][] C = new int[m + 1][m + 1];           // Pascal's triangle
    for (int j = 0; j <= m; j++) {
        C[j][0] = 1;
        for (int i = 1; i <= j; i++) C[j][i] = addMod(C[j - 1][i - 1], i <= j - 1 ? C[j - 1][i] : 0, M);
    }
    long[] exact = new long[m + 1];
    for (int j = 0; j <= m; j++) {
        long v = powMod(j, n, M);                // strings over j letters, no condition
        for (int i = 0; i < j; i++)              // remove those using only i of the letters
            v = subMod((int) v, (int) (C[j][i] * exact[i] % M), M);
        exact[j] = v;
    }
    return (int) exact[m];
}
static long powMod(long b, long e, long M) {
    long r = 1;
    for (b %= M; e > 0; e >>= 1, b = b * b % M) if ((e & 1) == 1) r = r * b % M;
    return r;
}

        b = b * b % M

### sos
--idea
SOS DP (sum over subsets) computes, for every mask (a number whose bits mark a chosen set of items), the sum of a value `a[s]` over all subsets `s` of that mask. Doing it directly costs 3 to the power `n` (every mask against all its submasks). SOS DP does it in `n * 2^n`.
The idea: add the bits one at a time. After handling bits `0..i`, `f[mask]` is the sum over subsets `s` of `mask` that differ from `mask` only in bits `0..i`. Handling the next bit `i + 1` means: a mask with that bit set also collects the sum of the mask without that bit (all of whose subsets are the subsets of `mask` that leave bit `i + 1` off).
--build
Small steps:
1. State: after finishing bit `i`, `f[mask]` is the sum of `a[s]` over all `s` that are subsets of `mask` and agree with `mask` on all bits above `i` (they may differ only in bits `0..i`).
2. Base case (before any bit): `f[mask] = a[mask]`. Only `s = mask` itself qualifies.
3. Transition for bit `i`: for every `mask` that has bit `i` set, `f[mask] += f[mask without bit i]`. The first part `f[mask]` counts subsets that keep bit `i` on, the added part counts subsets that turn it off. The test and the removal are the code pieces `getBit` and `clearBit`.
4. Order to fill: bits `i` from 0 to `n - 1` in the outer loop, masks in any order in the inner loop (the value read, the mask without bit `i`, is never changed during bit `i`'s pass, because it has bit `i` clear).
5. Read the answer: `f[mask]` for every mask, after all bits are done.
Variants: sum over supersets (flip the test: if bit `i` is clear, `f[mask] += f[mask with bit i]`), and other operations such as max, or counting, in place of the sum (anything with an order-free combine, `+`, `max`, `or`). For inclusion-exclusion, subtract instead of add.
--think
- Signal: "for every mask, combine over its submasks (or supermasks)", counting pairs with `a AND b = c` or with `a AND b = a`, "the number of elements that are subsets of x". If the naive solution enumerates submasks of every mask, the cost is 3 to the `n`, and SOS reduces it to `n * 2^n`.
- Reverse it by the same loops with subtraction: the inverse of the subset sum recovers `a` from `f`. This is the Mobius transform, and is used for subset convolution and AND, OR counting.
- Pairs with `a OR b` equal to a given mask: take the subset sums of the counts, square them per mask, then invert.
- Memory: one array of `2^n` values.
- Neighbours: bitmask DP, submask enumeration DP (3 to the `n`, for transitions that really combine two submasks), inclusion-exclusion DP.
- Pitfalls: the loop order (bits must be the outer loop; masks outer and bits inner gives a different, wrong result); updating in place is fine only for this order; overflow when summing many values.
--cost
Time O(n times 2^n). Space O(2^n).
--java
static long[] sumOverSubsets(long[] a, int n) {
    long[] f = a.clone();                        // before any bit: only s = mask
    for (int i = 0; i < n; i++)                  // bits outside
        for (int mask = 0; mask < (1 << n); mask++)
            if (getBit(mask, i))                 // code piece: is bit i set?
                f[mask] += f[clearBit(mask, i)]; // add the subsets with bit i off
    return f;
}

### profile
--idea
Broken profile DP counts tilings of a grid (here, with 1 by 2 dominoes) by sweeping over the cells one at a time, row by row, and remembering a profile: for the next `m` cells in sweep order (a whole row's width), which are already covered by a domino placed earlier. The profile is a bitmask of `m` bits, so the table has `2^m` entries, and `m` should be at most about 15 to 20. "Broken" means the boundary is a staircase that moves one cell at a time, not a straight line between rows.
Why it works: when you reach a cell, everything that can still affect it is a domino that already sticks out into it, from the cell above (vertical) or from the left (horizontal). Those are exactly the bits of the profile.
--build
Small steps:
1. Grid has `n` rows and `m` columns. Sweep cells `(i, j)` in row order. Bit `j` of `mask` says whether the cell that the sweep will reach in column `j` next (the cell `(i, j)` if not yet passed in this row, otherwise `(i + 1, j)`) is already covered. Bits above `j` refer to row `i`, bits below `j` refer to row `i + 1`.
2. State: `dp[mask]` is the number of ways to place dominoes so that all cells before the current one are covered and the profile is `mask`.
3. Base case: `dp[0] = 1` before the first cell (nothing is covered).
4. Transition at cell `(i, j)`, for each `mask` with `dp[mask] > 0`:
 - If bit `j` is set (the cell is covered): move on, clearing the bit (the cell below is not yet covered): `new[clear(mask, j)] += dp[mask]`.
 - Otherwise place a vertical domino if `i + 1 < n`: it covers this cell and the one below, so set the bit: `new[set(mask, j)] += dp[mask]`.
 - Otherwise place a horizontal domino if `j + 1 < m` and bit `j + 1` is clear: it covers this cell and the next in the row, so set bit `j + 1`: `new[set(mask, j + 1)] += dp[mask]`. Bit `j` stays clear because the cell below is not covered.
 The tests and changes of bits are the code pieces `getBit`, `setBit` and `clearBit`.
5. Order to fill: all cells in row-major order; each cell builds a new table `new` from `dp`, then `dp = new`.
6. Read the answer: after the last cell, `dp[0]` (every cell covered and nothing sticks out below the grid).
--think
- Signal: tiling or filling a grid with small shapes, one dimension small (at most about 15 to 20), the other large; "count the ways to place", "can the grid be fully covered".
- State choice: one bit per column of the frontier. For shapes taller than a domino, use a profile of several states per column (base 3 or more), or a profile that spans more than one row.
- Why cell-by-cell is better than row-by-row: the row-by-row version loops over pairs of masks (4 to the `m`), while the cell version does O(1) transitions per mask per cell, which is `n * m * 2^m` in total.
- Neighbours: bitmask DP (the profile is a mask), digit DP (position by position), matrix exponentiation (for a very long grid, the transition between row profiles is a matrix of size 2^m, raised to a power).
- Pitfalls: mixing up what bit `j` means (the same bit means "cell in this row" for columns not yet swept and "cell in the next row" for columns already swept); horizontal domino across the last column; the answer must be `dp[0]`, not the sum of everything; a grid with an odd number of cells is 0.
--cost
Time O(n times m times 2^m). Space O(2^m).
--java
static long domino(int n, int m) {
    long[] dp = new long[1 << m];
    dp[0] = 1;                                   // nothing covered yet
    for (int i = 0; i < n; i++)
        for (int j = 0; j < m; j++) {
            long[] nx = new long[1 << m];
            for (int mask = 0; mask < (1 << m); mask++) {
                if (dp[mask] == 0) continue;
                if (getBit(mask, j)) nx[clearBit(mask, j)] += dp[mask];   // already covered
                else {
                    if (i + 1 < n) nx[setBit(mask, j)] += dp[mask];       // vertical
                    if (j + 1 < m && !getBit(mask, j + 1))
                        nx[setBit(mask, j + 1)] += dp[mask];              // horizontal
                }
            }
            dp = nx;
        }
    return dp[0];
}

### dpperm
--idea
DP on permutations builds an ordering of `n` items one position at a time, remembering only which items are already placed (a bitmask) and, when the rule looks at neighbours, which item was placed last. There are `n!` orderings but only `2^n` subsets, so with `n` up to about 20 the DP is much cheaper than listing them.
Example: count the orderings (permutations) of `n` distinct items in which every two adjacent items are compatible, given a table `ok[a][b]` that is 1 when `a` may be directly followed by `b`.
--build
Small steps:
1. State: `dp[mask][last]` is the number of ways to order exactly the items in `mask` so that the ordering ends with item `last` (which is in `mask`) and every adjacent pair so far is compatible.
2. Base case: `dp[1 << i][i] = 1` for every item `i` (an order of one item).
3. Transition: for each `mask` and each `last` in it with `dp[mask][last] > 0`, and each item `nxt` not in `mask` with `ok[last][nxt] == 1`, add `dp[mask][last]` to `dp[mask | (1 << nxt)][nxt]`. The items in a set, and the items outside it, are listed by the code piece `itemsIn(mask, n)` and `itemsIn(full ^ mask, n)`.
4. Order to fill: `mask` from 1 up to `full - 1`, where `full = 2^n - 1`; adding a bit only makes the number bigger.
5. Read the answer: the sum of `dp[full][last]` over all `last`.
What must hold: the rule for the next item depends only on the set so far and the last item. If the rule looks further back (two last items), put them in the state; if it depends on the position, include `popcount(mask)`, which is already known from the mask.
--think
- Signal: "count or optimise over orderings", `n` at most about 20, rules about neighbours in the order (no two adjacent items that are close, squareful permutations, a cost for each consecutive pair).
- The same DP with `min` over costs is the travelling salesman path; with `max` it is a scheduling problem. Counting orders with duplicate items needs a division by the factorial of the counts, or a mask over distinct items only.
- If the cost of placing an item depends on the number already placed (a weight times its position), the position is `popcount(mask)`, so no extra state is needed.
- Neighbours: bitmask DP, travelling salesman DP, assignment DP (the same masks without a last item), inclusion-exclusion DP (counting orderings that avoid something).
- Pitfalls: `n` too large (memory `2^n * n`); forgetting the base case for single items; counting an ordering twice because of duplicate values.
--cost
Time O(2^n times n squared). Space O(2^n times n).
--java
static long countOrders(int[][] ok) {
    int n = ok.length, full = (1 << n) - 1;
    long[][] dp = new long[full + 1][n];
    for (int i = 0; i < n; i++) dp[1 << i][i] = 1;       // an order of one item
    for (int mask = 1; mask < full; mask++)
        for (int last : itemsIn(mask, n)) {
            if (dp[mask][last] == 0) continue;
            for (int nxt : itemsIn(full ^ mask, n))      // items not placed yet
                if (ok[last][nxt] == 1) dp[mask | (1 << nxt)][nxt] += dp[mask][last];
        }
    long total = 0;
    for (int last = 0; last < n; last++) total += dp[full][last];
    return total;
}

### optbst
--idea
An optimal binary search tree (BST) arranges sorted keys in a search tree so that the expected search cost is smallest, given how often each key is looked up. A key at depth 1 (the root) costs 1 comparison per lookup, a key at depth 2 costs 2, and so on. The total cost is the sum of `frequency * depth`. Frequent keys should sit near the top, but the tree must stay a valid search tree (smaller keys to the left, larger to the right).
The insight: whichever key `r` is the root of a range of keys, the left keys form its left subtree and the right keys its right subtree, and each of these is an optimal tree of its own range. Also every key in the range is one level deeper than it would be in its own subtree, which adds the total frequency of the range once.
--build
Small steps:
1. Keys are numbered `1..n` in sorted order with frequencies `f[1..n]`. Let `pre` be prefix sums, so the total frequency of keys `i..j` is `pre[j] - pre[i-1]`.
2. State: `dp[i][j]` is the least total cost of a search tree on keys `i..j`. An empty range (`j = i - 1`) costs 0.
3. Transition: `dp[i][j] = (pre[j] - pre[i-1]) + min over r from i to j of dp[i][r-1] + dp[r+1][j]`. The key `r` is the root, and adding the whole range's frequency accounts for pushing everything one level down.
4. Base case: `dp[i][i-1] = 0` for all `i` (empty ranges). The tables come from the code piece `newTable(n + 1, 0)`, which gives rows of `n + 2` zeros, enough to hold `dp[i][i-1]` and `dp[r+1][j]` when `r = j`.
5. Order to fill: by range length from 1 to `n` (shorter ranges first), and for each length, every start `i`.
6. Read the answer: `dp[1][n]`.
--think
- Signal: a sorted sequence, a tree built over it (search tree, merge tree, triangulation), cost depending on depth or on a total over the range. The state is a range and the transition picks the root, which is the same shape as matrix chain and burst balloons.
- The root choice must split the range into independent left and right problems. That is why choosing the root (the last thing decided from the top) works.
- This version is O(n cubed). Knuth optimisation applies here (the best root `root[i][j-1] <= root[i][j] <= root[i+1][j]`), bringing it to O(n squared): see the Knuth lesson.
- Variants: also counting failed searches (add gap frequencies between keys), and Huffman coding (no key order constraint, solved greedily).
- Neighbours: interval DP, matrix chain, Knuth optimisation, burst balloons.
- Pitfalls: using depth starting at 0 (then the root costs 0: add the total frequency only when the problem counts the comparisons that way); forgetting the empty ranges; off-by-one at `r - 1` and `r + 1`.
--cost
Time O(n cubed). Space O(n squared).
--java
static long optimalBst(int[] f) {                // f[0..n-1] are the frequencies
    int n = f.length;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + f[i];
    long[][] dp = new long[n + 2][];
    for (int i = 0; i < n + 2; i++) dp[i] = newTable(n + 1, 0);   // empty ranges cost 0
    for (int len = 1; len <= n; len++)
        for (int i = 1; i + len - 1 <= n; i++) {
            int j = i + len - 1;
            long best = Long.MAX_VALUE;
            for (int r = i; r <= j; r++)         // r is the root
                best = Math.min(best, dp[i][r - 1] + dp[r + 1][j]);
            dp[i][j] = best + pre[j] - pre[i - 1];
        }
    return dp[1][n];
}

### submask
--idea
A submask of a mask is a mask whose set bits are a subset of the mask's set bits. Submask enumeration DP is a bitmask DP whose transition looks at every subset of the current set: `dp[mask] = best over submasks sub of mask of dp[mask without sub] + cost[sub]`. Summed over all masks, the number of (mask, submask) pairs is 3 to the power `n`, because each item is either outside the mask, in the mask but not in the submask, or in both. So it works for `n` up to about 15 to 18.
Example: split `n` items into groups (a set partition) so that the total of `cost[group]` is smallest, where `cost` is given for every non-empty subset of items.
--build
Small steps:
1. A set of items is a mask; item `i` is in it when bit `i` is set. `cost[sub]` is given for every non-empty mask `sub`.
2. State: `dp[mask]` is the least total cost to split exactly the items of `mask` into groups.
3. Base case: `dp[0] = 0` (no items, no groups).
4. Transition: `dp[mask] = min over non-empty submasks sub of mask of dp[mask ^ sub] + cost[sub]`. Here `sub` is the group that contains some items, and the rest `mask ^ sub` (the items of `mask` not in `sub`) is split by an earlier state. The code piece `submasks(mask)` lists every non-empty submask (it runs `sub = (sub - 1) & mask` from `mask` down to 1).
5. Order to fill: `mask` from 1 to `2^n - 1` in increasing order; `mask ^ sub` is smaller than `mask`, so it is ready.
6. Read the answer: `dp[(1 << n) - 1]`.
Speed-up that halves the work and removes duplicate orderings: require the group `sub` to contain the lowest set bit of `mask`; the partitions are still found once each. The cost per mask is then a sum over 2 to the (bits - 1) submasks.
--think
- Signal: partition a set into groups, cover with a few sets, "assign each subset to a team", with `n` at most about 18 and a cost or validity for each subset. The combination of a small `n` and "any group" is the hint.
- If a group's cost can be computed from the items only (the sum, the maximum, an OR), precompute `cost[sub]` for all subsets first, each in O(1) from the one without its lowest bit.
- Count the real work: 3 to the 16 is 43 million, to the 18 is 387 million; beyond that look for another formulation (a profile, an ordering DP, or inclusion-exclusion).
- If only a fixed number of groups is allowed, add the group count to the state (`dp[groups][mask]`, then 3 to the `n` times `k`). Some counting versions use SOS DP or subset convolution to do the combination faster.
- Neighbours: bitmask DP (the base idea), SOS DP (sum over submasks in `n * 2^n` when the combination is a plain sum), assignment DP, broken profile DP.
- Pitfalls: enumerating the empty submask (an endless loop or a useless transition); iterating `sub` upward instead of the downward trick; forgetting that the enumeration visits `sub` and also its complement as different transitions.
--cost
Time O(3^n). Space O(2^n).
--java
static long minPartitionCost(long[] cost, int n) {      // cost[sub] for every mask sub >= 1
    int full = (1 << n) - 1;
    long INF = Long.MAX_VALUE / 4;
    long[] dp = new long[full + 1];
    Arrays.fill(dp, INF);
    dp[0] = 0;                                   // no items, no groups
    for (int mask = 1; mask <= full; mask++)
        for (int sub : submasks(mask))           // code piece: non-empty submasks
            dp[mask] = Math.min(dp[mask], dp[mask ^ sub] + cost[sub]);
    return dp[full];
}
